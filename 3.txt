# OLP edge-case audit

**Repository:** `olp-main(11)(3)`  
**Inventory:** 130 distinct edge cases  
**Severity:** 0 critical, 12 high, 78 medium, 40 low  
**Method:** repository-wide static source review of the Rust gateway/control plane, storage, providers/protocols, Svelte console, Helm deployment, tests, and CI.

## Audit limits

This is an exhaustive best-effort static inventory, not a proof that no other edge case exists. The environment did not contain the project Rust toolchain, and the console requires Node 24 while the available runtime is Node 22; therefore I did not claim compile/test/runtime confirmation. `Confirmed` means the control/data flow is directly present in source. `High confidence` means the behavior follows from the implementation but still benefits from an executable regression test. `Test required` and `Contract-dependent` findings are deliberately not presented as proven defects.

The codebase already contains unusually broad unit, PostgreSQL/Valkey integration, HA fault-injection, fuzz, protocol, SDK, browser, and deployment coverage. The gaps below cluster around long timing windows, crash boundaries, malicious-but-parseable provider output, distributed clock/order assumptions, and valid high-cardinality operator input.

## Fix first

- **E-001 — Valid long-lived responses are terminated by connection age** (High, Confirmed). Every accepted connection is shut down after roughly 5 minutes plus a 30-second drain, regardless of a route/provider timeout. A valid long stream or download is truncated; an HTTP/2 stream opened late inherits only the connection’s remaining lifetime.
- **E-004 — Shutdown accounting closes an epoch from a pre-drain snapshot** (High, Confirmed). The loss reporter waits a fixed 100 ms instead of joining the request-metadata writer. A slow in-flight XADD can persist after the epoch is closed, causing permanent false uncertainty or an inconsistent loss boundary.
- **E-016 — Provider-reported usage above total reservation is not charged** (High, Confirmed). The gateway reserves an HTTP estimate plus a parsed-operation delta, but reconciliation only refunds over-reservation. If actual provider usage exceeds the combined estimate, TPM accounting remains low.
- **E-040 — Crash or SIGKILL leaves private media spool trees forever** (High, Confirmed). Each process creates a new directory and removes it only in Drop. A node crash, power loss, abort, or SIGKILL leaves all prior files without a startup scavenger.
- **E-044 — Image response has no aggregate output/file-descriptor bound** (High, Confirmed). Per-image size is bounded, but an arbitrary response count can open many handles and build a very large aggregate JSON/stream. This can exhaust FDs, memory, or response time.
- **E-053 — Side-effecting operations may fail over after ambiguous upstream execution** (High, Contract-dependent). Post-send 5xx, rate-limit, or retryable canonical errors can permit failover for image/audio/video operations. If the first provider accepted work before returning/losing the response, a second target can duplicate and bill it.
- **E-059 — Vertex OAuth refresh can be held indefinitely by a trickling body** (Medium, Confirmed). Each chunk has a timeout, but no total response deadline exists. A token endpoint sending one small chunk inside every idle window holds the shared refresh mutex indefinitely and queues all token consumers.
- **E-072 — Request-metadata Valkey stream is unbounded** (High, Confirmed). Gateways XADD without MAXLEN/XTRIM. When Valkey is healthy but PostgreSQL or the consumer is unhealthy, accepted events accumulate until Valkey memory pressure affects limits, runtime hints, or the whole service.
- **E-073 — One valid-but-invalid-for-DB event can poison the entire metadata consumer** (High, Confirmed). Negative media units/tokens, invalid numeric range, or another DB constraint failure is not classified as InvalidRequestMetadataEvent. The consumer retries/breaks on the same entry forever, so later entries pile up.
- **E-080 — Fresh-start runtime recovery only searches the newest 32 releases** (High, Confirmed). SQL LIMIT is applied before envelope/authentication/compatibility filtering. Thirty-two corrupt, undecryptable, or incompatible newest rows hide an older valid last-known-good runtime and keep a replacement node unready.
- **E-082 — Pricing revision creation holds a global advisory lock during serial work** (Medium, Confirmed). A valid request can contain up to 10,000 entries. It performs provider validation and insertion serially inside one transaction/global lock, monopolizing a connection and blocking every pricing writer.
- **E-086 — UUIDv7-only cursors can skip later commits under clock skew** (Medium, Confirmed). Rows are paged by UUID ordering. A node with a behind clock can commit a newly created UUID lower than a cursor already issued by another node, so forward pagination never returns it.
- **E-095 — Successful upstream create can lose its only recoverable ID** (High, Confirmed). After upstream create succeeds, attaching the upstream ID gets only three very short DB retries. If PostgreSQL remains down, the reservation has no ID; restart can only mark create ambiguous and cannot discover or delete the potentially billable job.
- **E-096 — Local and provider media-job ID validators disagree** (High, Confirmed). The local store accepts a much broader <=1024-character ID; the OpenAI transport accepts only <=256 ASCII alnum/-/_. A persisted locally valid ID can become permanently unqueryable/undeletable.
- **E-125 — Helm monitoring rules page on intentionally disabled components** (Medium, Confirmed). Rules always expect both gateway and control metrics. A valid single-component deployment continuously alerts that the disabled component is absent.

## Severity and confidence

- **High:** can lose accounting/durability, orphan or duplicate billable work, cause broad availability failure, or permanently skip data.
- **Medium:** material availability, correctness, security-boundary, operability, or resource-amplification failure.
- **Low:** compatibility, bounded DoS, confusing semantics, future footgun, or defense-in-depth gap.
- **Confirmed:** directly established by the source path. **High confidence:** strong static inference. **Test required:** timing behavior needs execution. **Contract-dependent:** impact depends on an upstream guarantee not encoded locally.

## Full inventory

## 1. Listener, HTTP boundary, routing, and shutdown

### E-001 — Valid long-lived responses are terminated by connection age

**High · Confirmed** — Every accepted connection is shut down after roughly 5 minutes plus a 30-second drain, regardless of a route/provider timeout. A valid long stream or download is truncated; an HTTP/2 stream opened late inherits only the connection’s remaining lifetime.

**Evidence / review locus:** `apps/olp/src/listener.rs:40-41,301-342`

**Mitigation / regression test:** Make lifetime configurable and stream-aware, or stop accepting new H2 streams before retirement while allowing active streams to finish up to their own deadlines. Add a >6-minute stream test.

### E-002 — HTTP/2 streams lack a per-stream request-establishment deadline

**Medium · High confidence** — A client can keep many streams in header/body establishment on one connection until the connection-age cutoff. The configured 100-stream concurrency therefore becomes a state-retention multiplier.

**Evidence / review locus:** `apps/olp/src/listener.rs:36-41,256-342`

**Mitigation / regression test:** Apply header/read/body establishment deadlines per stream and test slow headers plus incomplete bodies across 100 streams.

### E-003 — Shutdown watch can miss an already-published state

**Medium · Test required** — The listener waits on watch::Receiver::changed() without first inspecting borrow(). A receiver created after shutdown is published, or a scheduling race around subscription, may wait for a later change that never comes.

**Evidence / review locus:** `apps/olp/src/listener.rs:179-231,308-343`

**Mitigation / regression test:** Use borrow_and_update()/has_changed() or select on the current value. Add a deterministic Tokio test where shutdown is sent before the accept/connection task starts waiting.

### E-004 — Shutdown accounting closes an epoch from a pre-drain snapshot

**High · Confirmed** — The loss reporter waits a fixed 100 ms instead of joining the request-metadata writer. A slow in-flight XADD can persist after the epoch is closed, causing permanent false uncertainty or an inconsistent loss boundary.

**Evidence / review locus:** `apps/olp/src/cli/startup.rs:391-428`

**Mitigation / regression test:** Give the writer an explicit flush-and-stop protocol and join it before closing the epoch. Fault-test XADD latency above 100 ms.

### E-005 — Only one background worker has terminal failure wired into runtime shutdown

**Medium · Confirmed** — The request-metadata writer is watched during normal operation, while other spawned workers are generally observed only while shutting down. A panic or early return can silently remove reconciliation/maintenance behavior from a still-ready process.

**Evidence / review locus:** `apps/olp/src/cli/startup.rs:145-241,279-323,546-572`

**Mitigation / regression test:** Supervise every essential task and transition readiness or terminate on unexpected completion. Add panic injection for each worker.

### E-006 — Public admission classifies all non-inference traffic as management

**Medium · Confirmed** — Static assets, SPA fallbacks, malformed paths, and true management calls share the reserved management pool. Slow asset/unknown-path responses can consume capacity intended to preserve the control plane.

**Evidence / review locus:** `apps/olp/src/request_admission/public.rs:183-248; apps/olp/src/router.rs:123-133`

**Mitigation / regression test:** Separate management API, static console, health, and unknown-path pools; reject unknown paths before acquiring a scarce permit.

### E-007 — Admission permits are held for the full response body

**Medium · Confirmed** — A slow client reading a static response or a streaming response keeps the relevant permit, turning downstream backpressure into admission starvation.

**Evidence / review locus:** `apps/olp/src/request_admission/public.rs:183-248`

**Mitigation / regression test:** Release request-establishment permits after headers or use separate in-flight-stream/body quotas. Test a slow reader against management availability.

### E-008 — Client-controlled request IDs cross the trust boundary unchanged

**Medium · Confirmed** — A caller can spoof another request ID and inject high-cardinality values into logs/traces and responses, subject only to the general header budget. This weakens incident correlation and can increase telemetry cost.

**Evidence / review locus:** `apps/olp/src/router.rs:100,166-168,318-329`

**Mitigation / regression test:** Generate an internal ID unconditionally; preserve a validated external ID in a separate field with a small character/length policy.

### E-009 — Body transport failures are flattened into HTTP 413

**Medium · Confirmed** — to_bytes() errors, body timeouts, disconnects, and true size overflow all enter the same rejection path. Clients receive payload-too-large for failures that are actually timeout or transport errors.

**Evidence / review locus:** `apps/olp/src/request_admission/validation.rs:57-65; apps/olp/src/request_admission.rs:416-428`

**Mitigation / regression test:** Preserve typed body errors and map overflow to 413, deadline to 408/504, and disconnect/I/O to an appropriate transport response. Add each failure mode.

### E-010 — Equal outer and inner body deadlines create nondeterministic status mapping

**Low · High confidence** — Two approximately 30-second timers race. Near the boundary, scheduler order can decide whether the request becomes the outer timeout response or the inner 413 path.

**Evidence / review locus:** `apps/olp/src/router.rs:173; apps/olp/src/request_admission/validation.rs:57-65`

**Mitigation / regression test:** Use one authoritative deadline or deliberately stagger nested deadlines. Freeze time in a boundary test.

### E-011 — Duplicate Content-Type and Content-Encoding fields are accepted with first-value semantics

**Medium · Confirmed** — Different proxies/framework layers may combine or select duplicate headers differently. A request can be admitted under one interpretation and decoded under another.

**Evidence / review locus:** `apps/olp/src/request_admission.rs:337-370`

**Mitigation / regression test:** Reject duplicate singleton headers before routing/decoding and test split/combined header forms.

### E-012 — Management singleton headers use first-value semantics

**Medium · Confirmed** — Origin, CSRF, Idempotency-Key, and If-Match are read with HeaderMap::get(). Duplicate values can be interpreted differently by an upstream proxy, WAF, or later middleware.

**Evidence / review locus:** `apps/olp/src/management_api/common.rs:218-233,261-277,322-373`

**Mitigation / regression test:** Require exactly one valid value for security- and concurrency-sensitive singleton headers.

### E-013 — Missing static assets fall back to index.html with 200

**Low · Confirmed** — A partial deployment or stale HTML can request a nonexistent JS/CSS asset and receive HTML under a successful status, obscuring rollout failures and enabling bad cache entries.

**Evidence / review locus:** `apps/olp/src/static_console.rs:47-55`

**Mitigation / regression test:** Only SPA-fallback extensionless navigation routes; return 404 for asset-like paths and set nosniff.

### E-014 — Console CSP silently degrades when index parsing fails

**Medium · Confirmed** — Startup can succeed with inline hashes omitted. The console then fails at runtime, and an in-place index change also leaves the precomputed CSP stale.

**Evidence / review locus:** `apps/olp/src/static_console.rs:18-45; apps/olp/src/router.rs:109-113`

**Mitigation / regression test:** Treat index/CSP generation failure as startup failure and package assets immutably. Add deployment-integrity checks.

### E-015 — Configured connection count has no practical upper-bound validation

**Low · Confirmed** — Only zero is rejected before constructing a Tokio semaphore. Extreme values can exceed semaphore limits or reserve implausible state, turning a configuration typo into startup failure/panic.

**Evidence / review locus:** `apps/olp/src/cli/startup.rs:42-46; apps/olp/src/listener.rs:175-176`

**Mitigation / regression test:** Validate against Semaphore::MAX_PERMITS and a documented operational ceiling.

## 2. Admission, authentication headers, rate limits, and circuit breaking

### E-016 — Provider-reported usage above total reservation is not charged

**High · Confirmed** — The gateway reserves an HTTP estimate plus a parsed-operation delta, but reconciliation only refunds over-reservation. If actual provider usage exceeds the combined estimate, TPM accounting remains low.

**Evidence / review locus:** `crates/storage/src/limits.rs:96-120; apps/olp/src/gateway/limits.rs:12-102; apps/olp/src/gateway/telemetry.rs:118-149`

**Mitigation / regression test:** Reconcile signed delta: refund excess or atomically charge the shortfall, with a bounded debt policy. Test actual > HTTP + parsed estimate.

### E-017 — Missing actual usage never refunds an estimate

**Medium · Confirmed** — When a provider omits usage or stream termination loses it, the estimate remains fully charged. This is fail-closed but can deny later traffic for a full bucket, especially after provider/proxy faults.

**Evidence / review locus:** `apps/olp/src/gateway/telemetry.rs:118-149; crates/storage/src/limits.rs:96-120`

**Mitigation / regression test:** Define explicit unknown-usage policy and expose it separately from known actual usage; consider bounded conservative estimates per operation.

### E-018 — Limit release and reconciliation are one-shot short operations

**Medium · Confirmed** — A transient Valkey stall beyond 250 ms leaves concurrency leased until TTL and estimated tokens charged until bucket expiry. Repeated faults can create false throttling.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:40-92; apps/olp/src/gateway/limits.rs:199-222`

**Mitigation / regression test:** Queue idempotent release/reconcile work for retry, or execute a bounded background retry with metrics and durable uncertainty accounting.

### E-019 — Concurrency lease TTL derives from the maximum allowed route timeout

**Medium · Confirmed** — One API key permitted to use a pathological long-timeout route gets a long abandonment TTL even when calling a short route. Crashes retain scarce concurrency much longer than necessary.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:286-315; apps/olp/src/request_admission.rs:431-446`

**Mitigation / regression test:** Extract and authorize the actual route before reservation, then use its timeout plus a bounded grace period.

### E-020 — Route timeout accepts practically unbounded positive i32 milliseconds

**Medium · Confirmed** — A valid value can approach 24.8 days. It expands request deadlines and distributed lease TTLs and can pin resources across maintenance windows.

**Evidence / review locus:** `crates/storage/src/configuration/route_lifecycle.rs:68-75`

**Mitigation / regression test:** Set product-level minimum/maximum timeouts and separately cap lease TTL.

### E-021 — Duplicate API credential headers are not rejected

**Medium · Confirmed** — Authorization, x-api-key, and x-goog-api-key are selected with first-value semantics. Proxy combination/reordering can authenticate a different credential than the application expects.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:216-234,414-419`

**Mitigation / regression test:** Reject duplicates and reject requests carrying more than one credential mechanism unless a documented precedence rule requires it.

### E-022 — Transfer-Encoding compatibility is stricter than real proxy chains

**Low · High confidence** — Exact chunked-oriented validation can reject combined/case/OWS variants emitted by compliant intermediaries, or disagree with the HTTP server’s already-decoded body semantics.

**Evidence / review locus:** `apps/olp/src/request_admission.rs (transfer-encoding validation)`

**Mitigation / regression test:** Normalize according to RFC token-list rules or reject all externally supplied Transfer-Encoding behind a trusted proxy. Add conformance vectors.

### E-023 — Raw JSON route attribution can diverge from typed handler semantics

**Medium · Confirmed** — Admission extracts route/model-like fields from raw JSON before typed decoding. Duplicate keys, aliases, type mismatches, or endpoint-specific defaults can make limits/metadata attach to a route different from the one the handler uses.

**Evidence / review locus:** `apps/olp/src/request_admission.rs:431-446; apps/olp/src/gateway/endpoint_policy.rs:811-827`

**Mitigation / regression test:** Decode one canonical typed envelope once, reject duplicate critical keys, and derive admission plus execution from that object.

### E-024 — Inference methods with ignored bodies can still pay JSON-admission costs

**Low · High confidence** — A GET/DELETE endpoint carrying JSON may be buffered, depth-checked, and charged even if the eventual handler ignores its body. This creates surprising quota and latency behavior.

**Evidence / review locus:** `apps/olp/src/request_admission.rs:414-475`

**Mitigation / regression test:** Declare body policy per endpoint/method and reject unsupported bodies before reservation.

### E-025 — Token reservation occurs before all request validation completes

**Medium · Confirmed** — JSON depth or typed-decoding failure after hard-limit reservation releases concurrency but can retain the token estimate. Malformed traffic can consume TPM without reaching a provider.

**Evidence / review locus:** `apps/olp/src/request_admission.rs:414-475`

**Mitigation / regression test:** Validate bounded structure and typed operation before committing token reservation, or reliably reconcile invalid requests to zero.

### E-026 — API-key expiration uses each node’s application clock

**Medium · Confirmed** — Clock skew around expires_at can make one node accept a key while another rejects it. The same issue affects abrupt expiry during rolling deployments with time drift.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:251-255; apps/olp/src/request_admission/multipart.rs:185`

**Mitigation / regression test:** Use database time for credential validity or enforce clock-health/readiness and include skew tolerance explicitly.

### E-027 — Circuit breaker state is process-local

**Medium · Confirmed** — In a multi-replica gateway, each process independently probes and trips a bad target. An outage can receive N times the intended probe/load, and traffic behavior differs by replica.

**Evidence / review locus:** `apps/olp/src/circuit.rs:12-20`

**Mitigation / regression test:** Store target health centrally or use a hybrid local breaker with distributed probe ownership and jitter.

### E-028 — Tenant-scoped rate limits can poison a target-wide circuit

**Medium · Confirmed** — A 429 caused by one tenant/account can count as a target failure and suppress healthy traffic for unrelated tenants.

**Evidence / review locus:** `apps/olp/src/circuit.rs:149-156`

**Mitigation / regression test:** Classify rate-limit scope from provider metadata; do not trip global target health on caller-scoped quota errors.

### E-029 — One success immediately clears accumulated circuit state

**Medium · Confirmed** — An intermittently failing target can oscillate: a single successful probe erases history and admits a burst before failing again.

**Evidence / review locus:** `apps/olp/src/circuit.rs:81-86`

**Mitigation / regression test:** Use a closed-transition success threshold or decay failure history rather than deleting it on one success.

### E-030 — Cancelled half-open probes hold the probe gate until timeout

**Low · Confirmed** — If the owning request disappears, the half-open state remains unavailable for the configured duration, delaying recovery despite no active probe.

**Evidence / review locus:** `apps/olp/src/circuit.rs:69-75`

**Mitigation / regression test:** Use an owned guard whose Drop releases or reschedules probe ownership safely.

### E-031 — Permit acquisition and downstream cancellation can leave ambiguous accounting windows

**Medium · High confidence** — Cancellation between distributed reservation, local guard construction, provider dispatch, and telemetry finalization exercises different best-effort cleanup paths. Transient Valkey failure amplifies the ambiguity.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs; apps/olp/src/gateway/limits.rs`

**Mitigation / regression test:** Add cancellation injection at every await boundary and assert bounded lease/token error after expiry/reconciliation.

### E-032 — Usage capture keeps only one terminal usage observation

**Low · Confirmed** — If a provider emits more than one cumulative/non-cumulative usage event, later capture overwrites earlier state without validating monotonicity or semantics.

**Evidence / review locus:** `apps/olp/src/gateway/telemetry.rs:394-407`

**Mitigation / regression test:** Model provider-specific usage semantics, reject regressions, and aggregate deltas only when explicitly documented.

### E-033 — Very long allowed-route sets increase admission database/CPU work

**Low · High confidence** — Computing maximum timeout and authorization over a broad policy set makes every request sensitive to control-plane cardinality.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:286-315`

**Mitigation / regression test:** Bound policy cardinality and precompute effective admission policy in the runtime generation.

## 3. Multipart input, media spool, generated files, and streaming responses

### E-034 — Multipart admission reserves worst-case endpoint bytes rather than declared bytes

**Medium · Confirmed** — Tiny uploads consume the endpoint maximum reservation and one active parser slot per key. Legitimate small concurrent uploads can be serialized or rejected despite ample real capacity.

**Evidence / review locus:** `apps/olp/src/request_admission/multipart.rs:80-123; apps/olp/src/request_admission.rs:529-549`

**Mitigation / regression test:** Reserve incrementally from actual parsed bytes, with a small initial lease and hard cap.

### E-035 — Only one multipart parser may run per API key

**Medium · Confirmed** — A slow or stalled upload head-of-line blocks every other multipart request for that key, including tiny independent operations.

**Evidence / review locus:** `apps/olp/src/request_admission/multipart.rs:80-123`

**Mitigation / regression test:** Use byte-weighted concurrency or a small bounded parser count rather than a global one-per-key mutex.

### E-036 — Bracketed and unbracketed multipart aliases can coexist ambiguously

**Medium · Confirmed** — Fields such as name and name[] are not merged or rejected consistently; one is consumed and the other may remain as an extension/unknown field.

**Evidence / review locus:** `apps/olp/src/gateway/multipart.rs:112-117`

**Mitigation / regression test:** Canonicalize aliases before extraction and reject mixed forms.

### E-037 — Prefix matching accepts malformed indexed field names

**Medium · Confirmed** — Names like image[, image[evil, or image[0]suffix can enter repeated-file handling even though they are not valid indexed forms.

**Evidence / review locus:** `apps/olp/src/gateway/multipart.rs:134-143`

**Mitigation / regression test:** Parse the full field-name grammar and require a closing bracket with a decimal index or an exact documented alias.

### E-038 — Lexicographic multipart ordering misorders numeric indices

**Low · Confirmed** — BTree ordering places image[10] before image[2]. Order-sensitive multimodal prompts can be silently rearranged.

**Evidence / review locus:** `apps/olp/src/gateway/multipart.rs:134-143`

**Mitigation / regression test:** Parse numeric indices and sort numerically; reject duplicate indices and gaps if order is semantically meaningful.

### E-039 — Multipart boundary extraction is deliberately narrow

**Low · High confidence** — Quoted/escaped parameters, unusual whitespace, duplicate boundary parameters, and other legal-but-uncommon Content-Type forms can be rejected or interpreted differently from the multipart parser.

**Evidence / review locus:** `apps/olp/src/request_admission/multipart.rs:157-176`

**Mitigation / regression test:** Use one standards-compliant media-type parser and pass the same canonical boundary to admission and decoding.

### E-040 — Crash or SIGKILL leaves private media spool trees forever

**High · Confirmed** — Each process creates a new directory and removes it only in Drop. A node crash, power loss, abort, or SIGKILL leaves all prior files without a startup scavenger.

**Evidence / review locus:** `apps/olp/src/media_spool.rs:58-81,375-378`

**Mitigation / regression test:** Use a stable parent with ownership marker, scavenge stale process directories at startup, and monitor physical disk usage.

### E-041 — Windows spool privacy relies on default temporary-directory ACLs

**Medium · Confirmed** — The Unix path explicitly constrains permissions; the Windows path creates an ordinary directory without verifying an owner-only ACL. Security then depends on host policy.

**Evidence / review locus:** `apps/olp/src/media_spool.rs:403-414`

**Mitigation / regression test:** Create and verify a restrictive DACL or document/validate the required host ACL policy.

### E-042 — Logical spool accounting can understate physical disk usage

**Medium · High confidence** — Unlinking a file releases logical capacity while an open descriptor/handle can retain blocks. Concurrent producers can therefore stay under the logical cap while physical usage remains above it.

**Evidence / review locus:** `apps/olp/src/media_spool.rs; apps/olp/src/gateway/multipart.rs; apps/olp/src/json_media.rs`

**Mitigation / regression test:** Track live open-file ownership until close, and enforce/alert on filesystem free space independently of logical accounting.

### E-043 — Off-runtime cleanup can be skipped

**Low · Confirmed** — Several Drop paths spawn asynchronous cleanup only when a Tokio runtime handle is available. Destruction during runtime teardown can leave reservations or files for later TTL/startup cleanup.

**Evidence / review locus:** `apps/olp/src/gateway/multipart.rs:169-190; apps/olp/src/json_media.rs:114-126; apps/olp/src/gateway/limits.rs:305-323`

**Mitigation / regression test:** Provide synchronous fallback cleanup where safe and explicitly drain resources before runtime shutdown.

### E-044 — Image response has no aggregate output/file-descriptor bound

**High · Confirmed** — Per-image size is bounded, but an arbitrary response count can open many handles and build a very large aggregate JSON/stream. This can exhaust FDs, memory, or response time.

**Evidence / review locus:** `apps/olp/src/image_response.rs:80-108`

**Mitigation / regression test:** Bound image count and aggregate bytes before opening handles; stream with a small open-file window.

### E-045 — Detached image producer failure becomes a truncated response

**Medium · Confirmed** — A panic or I/O failure after response headers are committed can terminate the producer without a structured terminal error, leaving invalid/truncated JSON.

**Evidence / review locus:** `apps/olp/src/image_response.rs:80-108`

**Mitigation / regression test:** Wrap producer completion in an explicit terminal frame/trailer protocol and record failure in request outcome telemetry.

### E-046 — Generated media MIME is trusted rather than sniffed

**Low · Confirmed** — Provider-declared media type controls output labeling. Mislabeled content can be served under an unsafe or misleading type.

**Evidence / review locus:** `apps/olp/src/image_response.rs`

**Mitigation / regression test:** Allowlist media types and validate magic bytes for locally spooled binary outputs; add nosniff.

### E-047 — Streaming producer cancellation/panic can look like clean EOF

**Medium · Confirmed** — When the detached producer’s terminal channel is cancelled, the body emits no terminal tail and simply ends. Clients may interpret a partial answer as a successful complete stream.

**Evidence / review locus:** `apps/olp/src/streaming_response.rs:163-181`

**Mitigation / regression test:** Emit/record an explicit abnormal termination where protocol permits, and make accounting distinguish producer loss from normal EOF.

### E-048 — Terminal frame cardinality is enforced with an assert in a detached task

**Medium · Confirmed** — An encoder returning more than two terminal chunks panics outside ordinary request error handling. Final usage/accounting and terminal error emission may be skipped.

**Evidence / review locus:** `apps/olp/src/streaming_response.rs:61-65,219-292`

**Mitigation / regression test:** Return a typed error instead of asserting and contain every producer task with panic-to-outcome conversion.

### E-049 — Quiet SSE streams have no heartbeat

**Medium · High confidence** — Load balancers and proxies with idle timeouts can close a valid stream while the provider is still working, especially for long reasoning or media operations.

**Evidence / review locus:** `apps/olp/src/streaming_response.rs:189-203`

**Mitigation / regression test:** Send configurable comment heartbeats below the shortest supported intermediary idle timeout.

### E-050 — SSE responses omit anti-buffering/no-transform guidance

**Low · Confirmed** — Some reverse proxies can buffer or transform event streams, producing bursty delivery and false first-byte/idle timeout behavior.

**Evidence / review locus:** `apps/olp/src/streaming_response.rs:189-203`

**Mitigation / regression test:** Set Cache-Control: no-cache, no-transform and deployment-specific buffering headers where appropriate; document proxy requirements.

### E-051 — Cancellation between file creation and ownership transfer has many cleanup states

**Medium · High confidence** — Dropping at each await boundary can leave a file owned by a different guard than expected, especially during runtime teardown.

**Evidence / review locus:** `apps/olp/src/gateway/multipart.rs; apps/olp/src/json_media.rs; apps/olp/src/image_response.rs`

**Mitigation / regression test:** Add deterministic cancellation tests after create, write, flush, reopen, response-open, and final unlink; assert both quota and filesystem state.

### E-052 — Malformed provider cardinality can amplify per-item work before aggregate checks

**Low · High confidence** — A bounded response body may still decode into a very large number of tiny image/file descriptors or metadata objects.

**Evidence / review locus:** `apps/olp/src/image_response.rs; crates/protocols/src/openai`

**Mitigation / regression test:** Enforce object-count and aggregate-decoded-size limits during decoding, not only raw-body byte limits.

## 4. Provider transport, failover, codecs, and SSE protocol edges

### E-053 — Side-effecting operations may fail over after ambiguous upstream execution

**High · Contract-dependent** — Post-send 5xx, rate-limit, or retryable canonical errors can permit failover for image/audio/video operations. If the first provider accepted work before returning/losing the response, a second target can duplicate and bill it.

**Evidence / review locus:** `apps/olp/src/gateway/failover.rs:214-263,371-393,437-468; crates/domain/src/ports.rs:167-178`

**Mitigation / regression test:** For non-idempotent operations, require an upstream idempotency key or treat every post-send uncertain/retryable result as ambiguous. Test with a provider that creates work then returns 500.

### E-054 — DNS refresh is serialized behind one mutex

**Medium · Confirmed** — At refresh time, slow resolution or address validation blocks all concurrent requests that need the same pinned resolver state, and caller deadlines include lock contention.

**Evidence / review locus:** `crates/providers/src/http_egress/pinned.rs:74-143`

**Mitigation / regression test:** Use stale-while-revalidate with single-flight background refresh and preserve a bounded last-known-good address set.

### E-055 — Static IPv6 allocation checks age with the binary

**Medium · Confirmed** — Newly allocated public IPv6 ranges can be false-rejected until a code release updates the hard-coded classification.

**Evidence / review locus:** `crates/providers/src/http_egress.rs:81-105`

**Mitigation / regression test:** Use a maintained address-classification library/table and test IANA special-purpose updates as part of dependency/release maintenance.

### E-056 — Provider body attempt deadline is reported as idle timeout

**Medium · Confirmed** — After the first byte, expiry of the total attempt deadline maps to a body-idle error, obscuring whether bytes were flowing. Retry/failover policy and operator diagnosis can be wrong.

**Evidence / review locus:** `crates/providers/src/transport_io.rs:214-229`

**Mitigation / regression test:** Preserve separate absolute-attempt and inter-chunk-idle error variants throughout transport classification.

### E-057 — Zero-length chunks affect first-byte and idle semantics

**Medium · High confidence** — An empty DATA chunk can count as first response activity and reset idle timing despite delivering no payload. It can bypass empty-body detection or prolong a trickling response.

**Evidence / review locus:** `crates/providers/src/transport_io.rs:99-117,203-258,386-411`

**Mitigation / regression test:** Only non-empty payload bytes should satisfy first-byte/idle progress unless protocol metadata explicitly counts as progress.

### E-058 — Duplicate provider Content-Type headers use first-value semantics

**Medium · Confirmed** — An upstream/proxy can supply conflicting media types. Different layers may choose differently, yielding decoder confusion or inconsistent retry classification.

**Evidence / review locus:** `crates/providers/src/transport_io.rs:45-67`

**Mitigation / regression test:** Reject duplicate singleton response headers and normalize parameters with a media-type parser.

### E-059 — Vertex OAuth refresh can be held indefinitely by a trickling body

**Medium · Confirmed** — Each chunk has a timeout, but no total response deadline exists. A token endpoint sending one small chunk inside every idle window holds the shared refresh mutex indefinitely and queues all token consumers.

**Evidence / review locus:** `crates/providers/src/vertex/oauth.rs:333-351`

**Mitigation / regression test:** Apply a total response deadline and a small body cap independent of chunk progress; do not hold a global mutex across unbounded I/O.

### E-060 — Vertex refresh failure does not use a still-valid cached token

**Medium · Confirmed** — Once refresh_at is reached, a transient OAuth outage fails requests even if expires_at remains in the future. This turns proactive refresh into an avoidable outage.

**Evidence / review locus:** `crates/providers/src/vertex/oauth.rs:191-231`

**Mitigation / regression test:** On refresh failure, use the cached token until a safety margin before actual expiry, while surfacing degraded refresh health.

### E-061 — Vertex token_type comparison is exact

**Low · Confirmed** — A standards-compatible casing/whitespace variation around Bearer may be rejected even though token types are conventionally case-insensitive.

**Evidence / review locus:** `crates/providers/src/vertex/oauth.rs:179-183`

**Mitigation / regression test:** Trim and compare ASCII case-insensitively, while rejecting unsupported schemes.

### E-062 — SSE decoder rejects bare-CR line endings and initial BOM

**Medium · Confirmed** — Legal or commonly tolerated event streams using CR separators or a UTF-8 BOM fail parsing.

**Evidence / review locus:** `crates/protocols/src/sse.rs:128-147,175-196`

**Mitigation / regression test:** Implement the full event-stream line grammar and add WHATWG-style conformance vectors.

### E-063 — SSE retry-only control records are discarded

**Low · Confirmed** — dispatch consumes/resets retry before discovering there is no data event. A provider’s retry directive can disappear.

**Evidence / review locus:** `crates/protocols/src/sse.rs:191-215`

**Mitigation / regression test:** Apply retry state independently from event dispatch and test retry/id/event fields without data.

### E-064 — Pending SSE data is dispatched at EOF without a blank terminator

**Low · Compatibility-sensitive** — Some implementations require a blank line to dispatch. OLP’s EOF dispatch can accept a partially transmitted terminal event that another client would discard.

**Evidence / review locus:** `crates/protocols/src/sse.rs:150-161`

**Mitigation / regression test:** Document the choice or make strictness configurable; add truncated-stream vectors.

### E-065 — Sequence saturation permits repeated u64::MAX

**Low · Confirmed** — A saturating increment stops advancing at u64::MAX, so repeated maximum sequence values can remain acceptable. This is theoretical but violates strict monotonicity.

**Evidence / review locus:** `crates/domain/src/canonical/events.rs:114-145; crates/protocols/src/gemini/client_stream.rs:50-68; crates/protocols/src/anthropic/client_stream.rs:68-86`

**Mitigation / regression test:** Use checked_add and fail closed at exhaustion.

### E-066 — Response extension insertion order can shift array indices

**Medium · High confidence** — Extensions are sorted primarily by depth, with same-depth pointer order inherited from a lexical map. Applying /10 before /2 to an array can change subsequent indices or yield order-dependent output.

**Evidence / review locus:** `crates/protocols/src/extensions.rs:176-240`

**Mitigation / regression test:** Group array edits by parent and apply removals/insertions in a defined numeric order; test 2 versus 10 and sibling operations.

### E-067 — Request extension collision semantics can silently overwrite canonical fields

**Low · High confidence** — Extension merging into canonical JSON can collide with fields produced by the protocol encoder. Depending on order/policy, a plugin-like extension may replace a validated field or be silently dropped.

**Evidence / review locus:** `crates/protocols/src/extensions.rs`

**Mitigation / regression test:** Reject collisions with canonical paths unless explicitly allowed and covered by schema-level tests.

### E-068 — A raw body byte limit does not bound decoded object complexity

**Medium · Confirmed** — A compact JSON body can contain extreme nesting, object count, embedding dimensions, moderation categories, or many tiny outputs, causing CPU/memory amplification after transport checks.

**Evidence / review locus:** `crates/providers/src/transport_io.rs; crates/protocols/src/openai`

**Mitigation / regression test:** Enforce depth, array-count, vector-dimension, and operation-specific aggregate limits during deserialization/normalization.

### E-069 — Transcription segment timestamps and duration are not normalized

**Low · High confidence** — Negative duration, decreasing segment timestamps, end-before-start, or segments outside the total duration can pass the codec boundary.

**Evidence / review locus:** `crates/domain/src/canonical/results.rs:62-79; crates/protocols/src/openai/audio.rs:441-478`

**Mitigation / regression test:** Validate finite nonnegative duration and monotonic bounded segments before telemetry/storage or client response.

### E-070 — Moderation scores are not constrained to 0..1

**Low · Confirmed** — A syntactically valid JSON response can carry negative or greater-than-one category scores, and normalization copies them unchanged to the canonical result and client response.

**Evidence / review locus:** `crates/protocols/src/openai/moderation.rs:134-183`

**Mitigation / regression test:** Enforce the provider contract’s score range at normalization and add -0.1/1.1 fixtures.

### E-071 — Embedding count and vector dimensions lack operation-level aggregate caps

**Low · Confirmed** — A provider can return many vectors or unexpectedly huge dimensions within the raw body cap, causing allocation and downstream serialization amplification.

**Evidence / review locus:** `crates/protocols/src/openai/embeddings.rs:154-216,278-301`

**Mitigation / regression test:** Validate response count against input count and cap dimensions plus total scalar elements.

## 5. Metadata ingestion, Valkey/PostgreSQL durability, runtime loading, and pricing

### E-072 — Request-metadata Valkey stream is unbounded

**High · Confirmed** — Gateways XADD without MAXLEN/XTRIM. When Valkey is healthy but PostgreSQL or the consumer is unhealthy, accepted events accumulate until Valkey memory pressure affects limits, runtime hints, or the whole service.

**Evidence / review locus:** `crates/storage/src/request_metadata/buffer.rs:187-203; crates/storage/src/valkey.rs:218-233`

**Mitigation / regression test:** Set an explicit retention/memory policy, trim only after a durable loss contract, and alert on bytes/length/oldest age—not just lag.

### E-073 — One valid-but-invalid-for-DB event can poison the entire metadata consumer

**High · Confirmed** — Negative media units/tokens, invalid numeric range, or another DB constraint failure is not classified as InvalidRequestMetadataEvent. The consumer retries/breaks on the same entry forever, so later entries pile up.

**Evidence / review locus:** `apps/olp/src/gateway/telemetry.rs:327-341; crates/storage/src/request_metadata/ingestion.rs:95-149; crates/storage/src/valkey.rs:143-209; crates/storage/migrations/0001_initial.sql:345-370`

**Mitigation / regression test:** Validate every DB invariant before enqueue; classify permanent SQL constraint/range errors into a dead-letter stream and continue, with an alert and raw event retained.

### E-074 — Negative provider duration can create the poison event

**High · Confirmed** — Transcription duration or video seconds can be negative and become media_units < 0. Application validation accepts it while PostgreSQL CHECK rejects it.

**Evidence / review locus:** `apps/olp/src/gateway/telemetry.rs:327-341; crates/domain/src/canonical/results.rs:62-79,107-121; crates/protocols/src/openai/audio.rs:441-478; crates/protocols/src/openai/video.rs:254-292`

**Mitigation / regression test:** Validate finite nonnegative media measures at provider normalization and again at ingestion; add malformed-provider fixtures.

### E-075 — Oversized Decimal values can poison ingestion

**Medium · High confidence** — A syntactically valid arbitrary-precision Decimal can exceed a PostgreSQL NUMERIC precision/scale even when it passes current application checks.

**Evidence / review locus:** `crates/storage/src/request_metadata/ingestion.rs:95-149; request metadata schema numeric columns`

**Mitigation / regression test:** Bound precision, scale, sign, and magnitude before enqueue and before insert; classify numeric overflow as permanent.

### E-076 — Metadata validation omits cross-field timing invariants

**Medium · Confirmed** — first-byte latency can exceed total latency, attempt timestamps can fall outside request timestamps, token components can be inconsistent, and other relational errors can persist or fail late.

**Evidence / review locus:** `crates/storage/src/request_metadata/ingestion.rs:95-149`

**Mitigation / regression test:** Centralize a complete RequestMetadataFact invariant validator and property-test it against the SQL schema.

### E-077 — Consumer health treats unknown lag as zero

**Medium · Confirmed** — When the server cannot report lag, unwrap_or(0) can present a healthy-looking zero rather than unknown/degraded.

**Evidence / review locus:** `crates/storage/src/valkey.rs:264-275`

**Mitigation / regression test:** Expose lag as optional/unknown and make readiness/alerts distinguish unavailable metrics from an empty backlog.

### E-078 — XACK/XDEL result counts are ignored

**Medium · Confirmed** — The consumer does not verify that the intended entry was acknowledged/deleted. Redis topology/race anomalies can silently leave or lose bookkeeping assumptions.

**Evidence / review locus:** `crates/storage/src/valkey.rs:218-233`

**Mitigation / regression test:** Check counts, metric unexpected zeros, and make duplicate persistence idempotent by event ID.

### E-079 — Consumer-group creation depends on matching BUSYGROUP text

**Low · Confirmed** — Error classification is coupled to an English server string. Proxy/version localization or changed wording can turn an expected existing-group condition into startup failure.

**Evidence / review locus:** `crates/storage/src/valkey.rs:95-106`

**Mitigation / regression test:** Use structured Redis error kind/code where available and test supported server/proxy variants.

### E-080 — Fresh-start runtime recovery only searches the newest 32 releases

**High · Confirmed** — SQL LIMIT is applied before envelope/authentication/compatibility filtering. Thirty-two corrupt, undecryptable, or incompatible newest rows hide an older valid last-known-good runtime and keep a replacement node unready.

**Evidence / review locus:** `apps/olp/src/cli/startup.rs:630-699; crates/storage/src/store/runtime.rs:19-63`

**Mitigation / regression test:** Page backward until a valid release is found or a documented retention boundary is reached; quarantine bad rows and alert.

### E-081 — Runtime outbox can publish duplicate hints

**Medium · High confidence** — Publishing before marking delivered is at-least-once. A crash between the steps republishes, and multiple workers without a claim lease can race on the same row. Hints may be idempotent but can create reload storms.

**Evidence / review locus:** `apps/olp/src/cli/commands.rs:231-245; crates/storage/src/store/runtime.rs:100-129`

**Mitigation / regression test:** Use SKIP LOCKED/claim leases plus event IDs and de-duplicate subscribers; explicitly test crash-after-publish.

### E-082 — Pricing revision creation holds a global advisory lock during serial work

**Medium · Confirmed** — A valid request can contain up to 10,000 entries. It performs provider validation and insertion serially inside one transaction/global lock, monopolizing a connection and blocking every pricing writer.

**Evidence / review locus:** `crates/storage/src/operations/pricing.rs:83-85,127-159,287-340`

**Mitigation / regression test:** Reduce the cap, validate providers in one set query, bulk insert, and minimize the locked critical section.

### E-083 — Pricing revision number can overflow in SQL before Rust validation

**Medium · Confirmed** — MAX(revision)+1 is computed in the database’s integer type. At the boundary, SQL overflow occurs before the application’s intended check/error mapping.

**Evidence / review locus:** `crates/storage/src/operations/pricing.rs:109-175`

**Mitigation / regression test:** Cast to bigint in SQL and perform an explicit bounded conversion, or use bigint revisions.

### E-084 — Pricing effective_at accepts extreme past/future values

**Medium · High confidence** — An operator can backdate a revision across already-accounted traffic or schedule it implausibly far ahead. Completion-time accounting around the boundary can then surprise billing/audit expectations.

**Evidence / review locus:** `apps/olp/src/operations/pricing.rs; crates/storage/src/operations/pricing.rs`

**Mitigation / regression test:** Define immutable historical periods, bounded scheduling windows, and explicit request-start versus completion-time pricing semantics.

### E-085 — Usage rollup can erase detail while request rows remain

**Medium · High confidence** — Request and usage retention are independently configurable. If request retention exceeds usage retention, old request-detail endpoints return a surviving request with null/missing usage and cost.

**Evidence / review locus:** `crates/storage/src/operations/requests.rs:107-157; crates/storage/src/maintenance.rs:101-149; crates/storage/src/operations/settings.rs:47-57`

**Mitigation / regression test:** Validate retention ordering or make the API explicitly report “usage rolled up/expired” rather than indistinguishable nulls.

### E-086 — UUIDv7-only cursors can skip later commits under clock skew

**Medium · Confirmed** — Rows are paged by UUID ordering. A node with a behind clock can commit a newly created UUID lower than a cursor already issued by another node, so forward pagination never returns it.

**Evidence / review locus:** `crates/storage/src/configuration/resources/api_keys.rs:6-11; routes.rs:6-11,400-406; providers.rs:9-52 and analogous lists`

**Mitigation / regression test:** Order by database-created_at plus immutable tie-breaker, or generate ordered IDs from one trusted clock/sequence. Add a skewed-ID integration test.

### E-087 — Database pool size accepts zero and extreme values

**Medium · High confidence** — A zero or huge max-connections value can make startup fail unexpectedly or overwhelm PostgreSQL after a typo/templating error.

**Evidence / review locus:** `apps/olp/src/cli/config.rs:49-55; crates/storage/src/store.rs:60-68`

**Mitigation / regression test:** Validate a sane nonzero range against deployment replica count and PostgreSQL capacity.

### E-088 — WriteOnlySecret can serialize plaintext

**Low · Confirmed** — Debug redacts the wrapper, but Serialize exposes the underlying secret. Reuse in an accidental response/logging envelope becomes a secret-exfiltration footgun.

**Evidence / review locus:** `apps/olp/src/management_api/common.rs:30-40`

**Mitigation / regression test:** Do not implement Serialize by default; provide a narrowly scoped request-only serializer/newtype.

### E-089 — Application and database clocks define different security/data boundaries

**Medium · High confidence** — Session/key checks use application time in places while persistence and ordering use database time. Skew produces inconsistent expiry, pagination, and audit boundaries across replicas.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:251-255; crates/storage/src/identity/invitations.rs:222-247; apps/olp/src/management_api/auth.rs:359`

**Mitigation / regression test:** Use database time for authoritative persisted validity or continuously gate readiness on tight clock synchronization.

### E-090 — Maintenance batches can race with detail reads and configuration changes

**Medium · High confidence** — Independent retention jobs and live reads can expose transient partial views, especially where facts are removed before aggregates or request rows.

**Evidence / review locus:** `crates/storage/src/maintenance.rs`

**Mitigation / regression test:** Delete/roll up in transactionally coherent order, expose retention state, and fault-test reads between each maintenance step.

### E-091 — Large stream event payloads have no explicit pre-deserialization cap

**Low · High confidence** — A corrupt/admin-injected stream entry can force a large String allocation and serde work before validation.

**Evidence / review locus:** `crates/storage/src/valkey.rs; crates/storage/src/request_metadata/buffer.rs`

**Mitigation / regression test:** Reject entries above a small documented byte ceiling and dead-letter them without blocking the group.

### E-092 — Unknown permanent SQL errors are retried as transient indefinitely

**Medium · High confidence** — The poison-event issue is broader than negative media: enum drift, string length, FK/config deletion, numeric overflow, or schema mismatch can all become permanent head-of-line blockers.

**Evidence / review locus:** `crates/storage/src/valkey.rs:143-209`

**Mitigation / regression test:** Classify SQLSTATEs into retryable versus permanent; dead-letter permanent failures with full audit data.

### E-093 — Route creation has no operation/target cardinality cap and performs serial transaction work

**Medium · Confirmed** — A syntactically valid route can contain a very large operation and target set. Validation, existence checks, and inserts run serially inside one transaction, tying up a connection and locks without malformed input.

**Evidence / review locus:** `crates/storage/src/configuration/route_lifecycle.rs:51-134`

**Mitigation / regression test:** Set explicit per-route caps, validate referenced IDs in bulk, and bulk insert after one set-based validation query. Add maximum-cardinality latency and cancellation tests.

### E-094 — Route replacement combines unbounded serial work with an O(n²) target merge

**Medium · Confirmed** — Replacement repeatedly scans existing targets with iter().find while processing an uncapped target list, then performs serial database changes. A valid operator request can self-DoS the control plane and hold locks for a long period.

**Evidence / review locus:** `crates/storage/src/configuration/resources/routes.rs:114-177`

**Mitigation / regression test:** Index existing targets by ID, cap collection sizes, use set-based diffs/bulk writes, and enforce a transaction-duration budget.

## 6. Media-job durability and reconciliation

### E-095 — Successful upstream create can lose its only recoverable ID

**High · Confirmed** — After upstream create succeeds, attaching the upstream ID gets only three very short DB retries. If PostgreSQL remains down, the reservation has no ID; restart can only mark create ambiguous and cannot discover or delete the potentially billable job.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:64-97,227-330; apps/olp/src/gateway/media_jobs.rs:62-81,182-220`

**Mitigation / regression test:** Use an idempotency key plus provider lookup, or durably record intent/result in a local/independent WAL before returning. Keep retrying ID attachment beyond ~75 ms with a bounded recovery contract.

### E-096 — Local and provider media-job ID validators disagree

**High · Confirmed** — The local store accepts a much broader <=1024-character ID; the OpenAI transport accepts only <=256 ASCII alnum/-/_. A persisted locally valid ID can become permanently unqueryable/undeletable.

**Evidence / review locus:** `apps/olp/src/gateway/media_jobs.rs:108-113; crates/providers/src/openai/transport/operations/video.rs:214-227`

**Mitigation / regression test:** Use one provider-specific validator before persistence and during migration/reconciliation; quarantine invalid legacy IDs with an operator recovery path.

### E-097 — Create failure cleanup depends on another one-shot database write

**Medium · Confirmed** — When ID attachment fails, marking cleanup-pending is itself one DB attempt. If that also fails, only logs retain the recovery gap.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:227-330`

**Mitigation / regression test:** Persist state transition through a durable retry queue/WAL independent of the failing transaction path.

### E-098 — Fixed reconciliation lease can expire during a slow provider call

**Medium · Confirmed** — Claims have a fixed two-minute lease. A slow list/get/delete or network stall can outlive it, allowing another worker to reclaim and issue duplicate operations.

**Evidence / review locus:** `crates/storage/src/media_jobs/reconciliation.rs:41-107`

**Mitigation / regression test:** Heartbeat/extend claims while active or derive lease from bounded provider deadline plus margin. Test a call over two minutes.

### E-099 — Reconciliation ordering can starve active jobs

**Medium · Confirmed** — Non-active/problem states are ordered ahead of active jobs. A sustained backlog of cleanup/anomalous rows can delay status refresh for valid active jobs indefinitely.

**Evidence / review locus:** `crates/storage/src/media_jobs/reconciliation.rs:74-86`

**Mitigation / regression test:** Use fair queues/quotas by state and track oldest age per class.

### E-100 — List refresh can return stale item state after provider failure

**Low · High confidence** — Listing performs provider refreshes with limited concurrency; on refresh failure, a stored item may remain in the response without a clear stale marker.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:342-415; apps/olp/src/gateway/media_jobs.rs:435-497`

**Mitigation / regression test:** Return per-item freshness/error metadata and do not imply live provider state.

### E-101 — A page can trigger up to 100 serially bounded provider reads

**Medium · Confirmed** — With concurrency four, one list request can occupy provider and gateway resources for many waves. Slow providers make management reads expensive and easy to amplify.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:342-415; apps/olp/src/gateway/media_jobs.rs:435-497`

**Mitigation / regression test:** Use stored status by default, explicit refresh, smaller caps, and a total refresh budget.

### E-102 — Malformed/absent provider expiry silently falls back to a local default

**Low · High confidence** — If expires_at cannot be parsed, a local 30-day-style fallback can misrepresent provider retention and cleanup urgency.

**Evidence / review locus:** `apps/olp/src/gateway/media_jobs.rs:220-266; apps/olp/src/gateway/videos.rs:218-219`

**Mitigation / regression test:** Expose unknown expiry explicitly and retain the raw provider value for diagnosis.

### E-103 — Reservation/reconciliation state machine needs crash injection at every transition

**Medium · High confidence** — The correctness contract spans reserve, create, attach ID, return, poll, delete intent, delete, and finalize. Every boundary has distinct duplicate/orphan behavior.

**Evidence / review locus:** `apps/olp/src/gateway/media_jobs.rs; crates/storage/src/media_jobs/reconciliation.rs`

**Mitigation / regression test:** Build a model-based crash/restart test matrix and assert no state loses both provider identity and actionable operator status.

## 7. OIDC, sessions, identity, and management API

### E-104 — OIDC callbacks fetch JWKS fresh with no last-known-good cache

### E-105 — OIDC flow-cookie eviction ignores server-side flow existence

### E-106 — Set-Cookie construction failure is silently ignored

### E-107 — Logout reports success even when server-side revocation fails

### E-108 — Cookie deduplication is quadratic within the header budget

**Low · Confirmed** — Repeated vector scans make many tiny cookie pairs O(n²). The 32 KiB bound limits impact but adversarial requests can waste CPU on every auth path.

**Evidence / review locus:** `apps/olp/src/request_cookies.rs:28-49`

**Mitigation / regression test:** Use a hash/indexed map while preserving explicit duplicate-security-cookie rejection.

### E-109 — Email canonicalization does not model provider-specific aliases or full IDNA policy

**Low · High confidence** — Trim/lowercase/basic syntax allows visually confusable Unicode/local-part variants and does not unify plus/dot aliases. Depending on product identity semantics, one human mailbox may obtain multiple accounts.

**Evidence / review locus:** `crates/storage/src/identity/invitations.rs:327-338; apps/olp/src/management_api/auth.rs:635`

### E-110 — No-op role/access updates still revoke sessions

**Medium · Confirmed** — Writing the same effective role/access state bumps the security version and invalidates sessions. Retried/idempotent operator automation can cause needless fleet-wide logouts.

**Evidence / review locus:** `crates/storage/src/identity/accounts.rs:111-172`

**Mitigation / regression test:** Compare effective state first and only bump security version on an actual privilege change.

### E-111 — Session validity around expiry differs under node clock skew

**Medium · High confidence** — Replicas using local time can disagree near expiration or idle boundaries, causing flapping 200/401 responses behind a load balancer.

**Evidence / review locus:** `apps/olp/src/management_api/auth.rs:359; crates/storage/src/identity/invitations.rs:222-247; apps/olp/src/request_admission/limits.rs:251-255`

**Mitigation / regression test:** Use database/server-issued monotonic expiry decisions or strict clock-health gates with a documented skew allowance.

### E-112 — Secret-file validation permits group readability

**Low · Confirmed** — The check rejects “other” permissions but allows group-read. Helm’s 0440/fsGroup makes this intentional, yet on a shared host an unexpectedly broad group can read master/provider secrets.

**Evidence / review locus:** `apps/olp/src/cli/validation.rs:48-59`

**Mitigation / regression test:** Verify owner/group identity, not only mode bits, and document the trusted group requirement.

### E-113 — Invitation verification performs expensive password work before token existence is known

**Low · High confidence** — Argon2 work for invalid tokens can be used as a bounded CPU amplifier. Existing semaphores/rate limits reduce impact but do not remove it.

**Evidence / review locus:** `apps/olp/src/management_api/access.rs:789-824; crates/storage/src/identity/invitations.rs:210-239`

**Mitigation / regression test:** Apply a cheap token format/MAC lookup first while preserving timing resistance for valid-looking tokens; retain strict rate limits.

### E-114 — Origin comparison can be brittle around canonicalization

**Low · High confidence** — Default ports, punycode, IPv6 textual forms, trailing dots, and scheme/host casing can make semantically identical origins compare differently—or custom parsing can normalize too much.

**Evidence / review locus:** `apps/olp/src/management_api/common.rs:218-233`

**Mitigation / regression test:** Parse as URL origin and compare canonical tuple; add hostile and equivalent-origin vectors.

### E-115 — Management If-Match behavior needs duplicate and stale-generation race tests

**Medium · High confidence** — Even after duplicate rejection, two operators can read the same version and race mutations across related resources where only one table/version is checked.

**Evidence / review locus:** `apps/olp/src/management_api/common.rs:345-373`

**Mitigation / regression test:** Use transaction-wide expected revision/generation and test cross-resource conflicts.

### E-116 — OIDC login availability depends on synchronous external network calls

**Low · High confidence** — Token exchange, discovery/JWKS retrieval, and identity persistence form a synchronous chain. A slow dependency consumes management admission and can amplify outage load.

**Evidence / review locus:** `apps/olp/src/oidc/callback.rs`

**Mitigation / regression test:** Set independent strict deadlines, cache immutable metadata, and isolate auth-network concurrency from other management traffic.

## 8. Console state, observability, deployment, and operational edges

### E-117 — Console can preserve an authenticated snapshot after passive validation network failure

**Medium · Confirmed** — A transient validation error leaves prior authenticated state visible. Server authorization remains authoritative, but stale sensitive UI/data can remain displayed on a shared or switched session.

**Evidence / review locus:** `console/src/lib/auth/lifecycle.ts:204-277`

**Mitigation / regression test:** Distinguish offline-stale from verified-authenticated state, hide sensitive cached views, and show last-validation time.

### E-118 — Cross-tab cookie/principal changes are not pushed into the console

**Medium · Confirmed** — Session/CSRF state is memory-only and revalidated mainly on focus/visibility or a freshness window. Another tab’s logout/login can leave stale principal data and CSRF state until a later trigger.

**Evidence / review locus:** `console/src/lib/auth/lifecycle.ts:189-328; console/src/routes/(console)/+layout.svelte:55-62`

**Mitigation / regression test:** Use BroadcastChannel/storage events plus server validation; clear principal-scoped caches immediately on any session-generation change.

### E-119 — A 403 does not trigger session/CSRF revalidation

**Medium · Confirmed** — Only 401 transitions auth state. A stale CSRF token or privilege downgrade often returns 403, causing repeated failed mutations while the UI still believes the old state.

**Evidence / review locus:** `console/src/lib/auth/lifecycle.ts:321-328`

**Mitigation / regression test:** Classify CSRF/session-generation 403 responses and force validation/token refresh without treating every authorization denial as logout.

### E-120 — Mutation freshness window can use stale CSRF/session state

**Medium · Confirmed** — When local validation is less than about 60 seconds old and a CSRF token exists, a mutation can skip revalidation even after another tab changes the session.

**Evidence / review locus:** `console/src/lib/auth/lifecycle.ts:279-300`

**Mitigation / regression test:** Bind CSRF to a session generation and propagate changes cross-tab; shorten or remove optimistic freshness for privilege-sensitive mutations.

### E-121 — Principal-scoped query caches can briefly display the previous principal’s data

**Low · High confidence** — If a cookie switches accounts while the SPA remains mounted, cached management responses can render until principal change is detected and caches are cleared.

**Evidence / review locus:** `console/src/lib/auth/lifecycle.ts:189-328; console/src/routes/(console)/+layout.svelte:55-62`

**Mitigation / regression test:** Namespace caches by immutable principal/session generation and blank protected views during revalidation.

### E-122 — Readiness stays HTTP 200 through important degraded subsystems

**Medium · Confirmed** — Limiter, metadata persistence, and reconciliation degradation can still produce ready=200. Depending on failure mode, the pod accepts traffic while accounting or cleanup guarantees are impaired.

**Evidence / review locus:** `apps/olp/src/observability.rs:403-470`

**Mitigation / regression test:** Expose policy-selectable readiness gates and separate “can serve” from “meets durability/accounting SLO.”

### E-123 — olp_ready metric reflects runtime readiness only

**Medium · Confirmed** — Alerting based on olp_ready can miss a dead metadata consumer, stuck reconciliation, or degraded limiter while HTTP readiness remains green.

**Evidence / review locus:** `apps/olp/src/observability.rs:473-507`

**Mitigation / regression test:** Export component readiness/age/last-success metrics and define composite SLO alerts.

### E-124 — Liveness is unconditional

**Low · Confirmed** — A process with a dead essential worker or wedged runtime can remain live forever, preventing restart.

**Evidence / review locus:** `apps/olp/src/observability.rs`

**Mitigation / regression test:** Use a conservative watchdog for essential event-loop progress while avoiding restarts for external dependency outages.

### E-125 — Helm monitoring rules page on intentionally disabled components

**Medium · Confirmed** — Rules always expect both gateway and control metrics. A valid single-component deployment continuously alerts that the disabled component is absent.

**Evidence / review locus:** `deploy/helm/templates/monitoring.yaml:1-55`

**Mitigation / regression test:** Condition each rule on the component’s enabled value and add helm-template tests for all enablement combinations.

### E-126 — Worker pods lack direct hung-loop health signals

**Medium · High confidence** — A worker can stay process-live while no longer consuming/reconciling. Kubernetes sees a healthy process unless an external lag alert catches it.

**Evidence / review locus:** `apps/olp/src/cli/startup.rs:145-241,546-572; apps/olp/src/observability.rs:403-507`

**Mitigation / regression test:** Expose last-success/progress endpoints or metrics and add watchdog thresholds based on expected workload.

### E-127 — Unknown-path and SPA traffic can distort management SLO metrics

**Low · High confidence** — Because non-inference traffic shares management classification, asset misses and internet scans can count against management saturation/latency and obscure real operator API health.

**Evidence / review locus:** `apps/olp/src/request_admission/public.rs:183-248; apps/olp/src/router.rs:123-133; apps/olp/src/observability.rs:403-507`

**Mitigation / regression test:** Tag route class before admission and keep separate unknown/static/management metrics.

### E-128 — Logs/metrics can explode cardinality from untrusted dimensions

**Medium · High confidence** — Client request IDs, model/route/provider labels, and malformed identifiers can create high-cardinality telemetry if emitted without allowlisting or hashing.

**Evidence / review locus:** `apps/olp/src/router.rs:318-329 and request/provider metadata paths`

**Mitigation / regression test:** Audit every metric label versus log field; cap/hash untrusted values and use stable internal IDs for labels.

### E-129 — Broad CI does not exercise long wall-clock and crash persistence boundaries by default

**Low · Confirmed** — The suite covers unit/integration/fuzz/HA/SDK/browser paths, but >5-minute streams, SIGKILL spool recovery, poison stream events, clock skew, and trickle endpoints require purpose-built tests.

**Evidence / review locus:** `.github/workflows/ci.yml; tests/README.md`

**Mitigation / regression test:** Add a nightly fault suite with virtual time where possible and real process crash/restart tests where durability is the invariant.

### E-130 — No Windows/macOS runtime matrix guards platform-specific spool behavior

**Low · High confidence** — Platform-specific ACL, file deletion, and open-handle semantics can regress unnoticed if production code remains nominally cross-platform but CI is Linux-centered.

**Evidence / review locus:** `.github/workflows/ci.yml`

**Mitigation / regression test:** Either declare Linux-only support or add focused platform jobs for filesystem/security semantics.

## Regression-test matrix

- **Connection retirement:** Start an HTTP/2 stream at connection age 4m59s and keep it valid beyond 6 minutes; verify policy does not truncate it unexpectedly.
- **Watch shutdown race:** Publish shutdown before spawning the listener/connection waiter and prove it exits immediately.
- **Shutdown metadata drain:** Delay XADD for >100 ms, initiate shutdown, and prove epoch closure occurs only after writer completion.
- **Poison metadata event:** Inject negative media units, NUMERIC overflow, FK failure, and oversized payload; prove each is dead-lettered and the next entry persists.
- **Valkey backlog:** Disable PostgreSQL while keeping Valkey healthy; verify bounded stream memory, oldest-age alerts, and explicit loss/degradation policy.
- **Usage surcharge:** Return actual usage above both HTTP and parsed estimates; assert the shortfall is charged atomically.
- **Media create crash matrix:** Crash after reserve, upstream create, ID receipt, each attach retry, cleanup-intent write, and response commit; assert recoverability.
- **Media ID grammar:** Fuzz provider IDs at 255/256/257/1024 bytes, Unicode, controls, slash, and whitespace; local and transport validators must agree.
- **Reconciliation lease:** Hold provider I/O over two minutes; prove only one worker owns the job through lease renewal.
- **Side-effect ambiguity:** Have provider create work then return 500/timeout; prove no second provider receives the operation without an idempotency guarantee.
- **Runtime LKG pagination:** Insert 33 invalid newest releases followed by one valid release; a fresh node must recover the valid one.
- **UUID cursor skew:** Insert a lower UUID after issuing a cursor; prove pagination returns it or document snapshot semantics.
- **Pricing cardinality:** Submit maximum entries and measure lock/transaction duration; enforce a bounded SLO and no global writer starvation.
- **Route replacement cardinality:** Use large operation/target sets, including target index 2 and 10; assert bounded runtime and deterministic ordering.
- **Vertex trickle:** Send one OAuth byte every nine seconds; total refresh deadline must fire and a still-valid cached token must remain usable.
- **JWKS outage/rotation:** Cache key A, take JWKS offline, validate A within stale window; then introduce unknown key B and require bounded refresh.
- **Duplicate singleton headers:** Exercise split and comma-joined duplicates for credentials, Origin, CSRF, If-Match, Content-Type, and Content-Encoding.
- **Multipart names:** Fuzz image[, image[evil, image[0]suffix, duplicate indices, name plus name[], and index 2/10 ordering.
- **Spool SIGKILL:** Kill the process with open and closed spool files, restart, and prove safe stale-tree scavenging and accurate disk accounting.
- **Image aggregate:** Return thousands of tiny images; enforce count, aggregate byte, and open-FD caps before response commitment.
- **Detached producer panic:** Panic every streaming/image producer after headers and after partial output; telemetry must record abnormal termination.
- **SSE conformance:** Cover BOM, CR, CRLF, LF, retry-only records, EOF without blank line, empty chunks, and terminal cardinality.
- **Cross-tab console:** Log out and log in as a different principal in another tab; no protected cache from the old principal may remain visible.
- **Helm component matrix:** Render gateway-only, control-only, both, and neither-invalid configurations; alerts must reference only enabled components.

## Important non-findings / narrowed assumptions

- The OIDC state, nonce, configuration-generation, and same-session security-operation bindings are comparatively strong; I did not find a direct state/nonce bypass in the reviewed path.
- The metadata consumer’s stable group/consumer name is not itself a lost-pending bug: startup drains pending entries before new entries. The real risks are unbounded backlog and permanent poison entries.
- Token accounting does include a second reservation after typed operation parsing. The finding is specifically actual provider usage above the **combined** reservation, not a missing parsed-operation reservation.
- Production media spooling uses the private constructor; test-only/nonprivate construction should not be reported as the production default.
- Several readiness/degraded-mode behaviors may be intentional product policy. They remain edge cases because the current metrics and Helm alerts do not make the weakened guarantees sufficiently explicit.

## Suggested repair order

1. Make metadata ingestion non-blocking on permanent bad events and bound the Valkey backlog.
2. Close the media-create identity durability gap and unify provider job-ID validation.
3. Fix connection retirement, shutdown writer joining, and essential-worker supervision.
4. Make accounting reconcile signed deltas and model unknown usage explicitly.
5. Remove side-effecting failover ambiguity or require upstream idempotency.
6. Page runtime LKG without a fixed pre-filter limit; replace UUID-only cursors.
7. Bound high-cardinality control-plane and response paths (pricing, routes, image count/bytes/FDs).
8. Add JWKS/token stale-if-error behavior, then harden duplicate headers, multipart grammar, console cross-tab state, and deployment alerts.
