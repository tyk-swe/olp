## Problem Statement

Developers use OpenLLMProxy to serve an inference request through a published route while retaining the selected model's native capability. Today, accepting an API-shaped request does not establish that the effective upstream invocation, returned events, or next interaction preserve its meaning. A recognized field can be consumed and then omitted; ordered content can be rearranged; a valid response can lose native state needed for a subsequent tool result. Preserving uninterpreted bytes alone does not make another provider execute their meaning.

The reviewed source already provides valuable runtime snapshots, route publication, credential slots, shared Attempt ownership, limits, resource affinity, accounting, media lifecycles, and a Svelte console. The problem is not the absence of those foundations or universal loss on native requests. It is that the shared generation representation, protocol/hosting coupling, and request-oriented compatibility checks do not enforce complete interaction fidelity. Provider configuration also needs independent semantic headers, operation-specific defaults, compatible cloud profiles, and per-connection networking controls.

Users need extensible API protocol → OpenLLMProxy Internal Format (OIF) → API protocol translation for generation and non-generation operations without hidden reductions in model intelligence or capability. They also need honest distinctions between native support, qualified translation, incompatibility, and incomplete or uncertain outcomes. A gateway that avoids degradation by rejecting nearly everything does not meet the breadth requirement.

## Solution

Implement a preservation-first, modular, in-process architecture that retains immutable source information in OIF and admits a qualified bidirectional interaction plan before dispatch. Both requests and results/events pass through OIF. Native identity plans and qualified translated plans share authorization, route admission, Attempt accounting, egress protection, and resource authority; native access is not an unrestricted tunnel.

A successful strict invocation must preserve four obligations: what the selected target executes, what the client observes, how permitted next actions can continue, and the effects/lifecycle of the work. The reference is an independently specified native invocation of the same upstream serving environment, not another provider's intelligence and not a native request generated by the mapper under test. Known incompatibilities fail before dispatch. Unexpected runtime violations produce an explicit incomplete/error outcome rather than a successful degraded response.

Native support covers the union of integrated provider capabilities. Qualified translation covers the documented and tested intersections of source protocol, target protocol, operation, model binding, client behavior, and delivery/lifecycle constraints. New provider-native capabilities can be exposed before a portable mapping exists, subject to policy coverage. No universal chat schema or OpenAI API becomes the mandatory intermediate representation.

Expose these contracts through schema-driven provider configuration, an effective-invocation and route-plan inspector, scoped qualification evidence, and operation-specific playgrounds. Retain the existing Go/Svelte deployment model and migrate incrementally without silently changing published legacy routes.

## Implementation Decisions

### D01 — Preserve the existing domain and operational authorities

Retain Inference request as one caller identity across Attempts; Route target as a provider model on a route; Credential slot as a provider-access choice; and the existing Attempt, Attempt budget, and Failover meanings. An Attempt can include a local target-quota refusal without provider dispatch. Do not replace these terms with ambiguous upstream-call counters.

Keep feature-owned transactions, immutable runtime publication, shared Attempt orchestration, PostgreSQL durable authority, Valkey coordination, resource mappings, credential handling, limits, usage accounting, and the Go/Svelte deployment model. Extend those owners rather than introducing parallel admission, retry, state, or billing services. Add OIF, dialect, provider profile, serving identity, interaction contract, and continuation terminology to the domain glossary as explicit additions, not replacements for existing concepts.

### D02 — Define the strict baseline and fidelity classes

The strict reference is an independently specified native invocation of the selected upstream serving identity with the same model-significant instructions, assets, controls, tools, defaults, headers, and state. Serving identity extends the existing provider-model binding with hosting/API profile, model/deployment/snapshot where exposed, upstream principal/account, region, resource scope, and observable serving revisions. A moving alias is not immutable; unknown provider internals remain unknown. Credential secret version is distinct from upstream principal identity.

Expose native-identity and qualified-interaction contracts separately from legacy or explicitly transformed behavior. No successful strict invocation may silently rewrite instructions, merge roles, truncate history, approximate reasoning settings, repair schemas, substitute hosted tools, downsample media, normalize vectors/scores, cache generated answers, or use a weaker substitute model. Blocking for security or policy is permitted, but must be reported as a local policy outcome, not fabricated provider success. Cross-provider support does not assert equal intelligence between different models; quality is relative to the selected target's native baseline.

### D03 — Make OIF source-preserving and operation-owned

OIF is an in-process envelope with operation/schema identity, source dialect/profile revision, immutable source-document/blob reference, operation-owned typed views, provenance, semantic requirements, assets/resources, delivery/lifecycle dimensions, and client contract. Requests, results, and events have separate types. The neutral envelope and operation contracts do not import provider SDKs or concrete transport/storage implementations.

Maintain one authoritative immutable source representation. Typed views derive from it; mapping passes produce validated overlays or a destination representation. Do not independently mutate native and canonical requests. Retain exact native subtrees/bytes where possible; enumerate allowed authentication, route-model identity, reversible resource-ID, and transport changes. Reject ambiguous or unsafe parsing; preserve numerical precision and Unicode, handle duplicate-key ambiguity explicitly, and enforce bounds. OIF is not a new mandatory public API, serialized internal RPC, or universal optional-field map.

### D04 — Preserve structure, presence, and semantic identity

Generation uses ordered content nodes with stable item IDs, role/scope identity, candidate branches, and tool-call/result dependencies. Tool calls remain in the same ordered sequence as text. Preserve native boundaries when they affect replay, schemas, cache placement, instructions, or model behavior. Causal relationships do not authorize reordering.

Retain source control names, dialect, presence, value, origin, units/budget scope, and applicable model/API constraints until an explicit lowering establishes equivalence. Absence, explicit null, false, zero, empty values, inherited defaults, and management reset are not interchangeable. Structured-output names/descriptions and schema strictness are requirements, not expendable metadata. A recognized/consumed field is not considered preserved until its execution, observation, or continuation obligation is discharged.

### D05 — Retain native capabilities without pretending they are portable

Native nodes identify their owner, revision, structural scope, original representation, and interpretation/replay constraints. Native identity forwarding can preserve new fields without defining a portable equivalent when authorization and policy coverage remain valid. Unknown behavior that defeats required policy inspection requires rejection or an updated authorized profile.

A foreign field retained in a sidecar is not executed by an incompatible target. A stored result is not automatically observable to the client. Distinguish retained, interpreted, projected, and reconstructed information. New native operations require a registered schema and authorized lifecycle/transport contract; new protocols still require real implementation.

### D06 — Link dialect, hosting, authentication, transport, and provider-model bindings

Implement independently owned components and a versioned provider profile that links only compatible combinations. Dialects own wire schemas, semantic lifting/lowering, errors, and event grammars. Hosting owns endpoint/resource addressing and cloud wrappers. Authentication owns credential resolution, token refresh, audiences/scopes, and signing. Transport owns framing and bounded I/O. Provider-model bindings own upstream model/deployment identity and resource constraints.

Keep OpenAI Chat and Responses distinct; separate Azure legacy and v1 profiles; separate Vertex publisher/dialect combinations; separate Bedrock Converse and model-specific Invoke profiles; and distinguish Gemini generation, stateful interaction, and live surfaces. Qualify actual provider/API revisions rather than inferring compatibility from a vendor name or URL. Final signing occurs after all signed path/body/header construction. A native API profile must not silently fall through a narrower Chat-shaped adapter.

### D07 — Keep extension cost local

Use trusted build-time registration at the composition root initially. A provider reusing a qualified dialect adds its profile, provider-model binding, schemas where needed, fixtures, and registration; it does not add provider cases to generic gateway logic. A new dialect adds its codecs, mappings, grammar, supported operations, and qualification fixtures. A new operation adds operation-owned contracts without modifying generation types.

Use separate unary, event, duplex, discovery, and resource interfaces where needed; do not force unrelated adapters to implement empty methods. Shared semantic mappings reduce implementation duplication but do not eliminate feature-interaction or cross-protocol qualification tests. Avoid a general compiler framework, arbitrary execution plugins, or a solver on the token path.

### D08 — Prepare the complete bidirectional interaction before dispatch

A prepared invocation contains the outbound builder, inbound result/event state machine, client projection and identity correspondence, next-turn reconstruction contract, upstream acceptance/retry rules, buffering/spooling/queue limits, evidence scope, and runtime guards.

Admission requires lowerable input, target interpretation of required semantics, observable required outputs, reconstructible permitted continuations, supported effects/lifecycle, and satisfied policy/resource constraints. Check candidate eligibility before cost, latency, health, or priority ranking. Revalidate live authorization and dynamic constraints at the appropriate existing admission boundary. Initial target selection establishes the native baseline; subsequent Failover must remain within the route's explicitly declared and qualified serving constraints. A matching model name does not establish interchangeable state or intelligence.

Compile schemas, compatible profile links, mapping templates, and bounded protocol grammars at activation. Bind request values and resolve resources at runtime. Cache bounded plan templates by relevant revisions, operation/mode, structural constraints, and policy; do not permit attacker-controlled schema diversity to create unbounded caches or expose public prompt fingerprints.

### D09 — Account for introduced behavior as well as omitted data

Produce a compact construction receipt covering source requirements, ordered relationships, destination settings/defaults introduced by OLP, identity rewrites, outputs, and reconstruction dependencies. Each disposition identifies a mapping rule and evidence scope. Retention alone cannot satisfy execution. Avoid duplicating prompts or opaque reasoning state in receipts or telemetry.

Qualification is attached to the operation, dialect/profile/codec revisions, provider-model binding constraints, client contract, execution dimensions, and tested feature combinations. Declared or discovered capability is not tested compatibility. Mapping assumptions and provider drift can stale affected evidence. A digest authenticates receipt provenance; it does not prove semantic truth.

### D10 — Provide precise failure and terminal contracts

Pre-dispatch incompatibility responses use stable machine-readable reasons, the affected source field or structural requirement when safe, and a non-secret explanation of the unsatisfied contract. Distinguish instruction-scope, reasoning-budget, state-carrier, target-capability, policy-conflict, and resource-affinity failures. Render errors in the admitted ingress error format with a correlated request identity.

Preserve local policy refusal, upstream refusal, upstream/provider error, cancellation, deadline, protocol violation, and incomplete/ambiguous transport outcome as different categories. Once streaming headers or data are committed, do not pretend an HTTP status can be changed retrospectively. Emit the protocol's supported terminal error/incomplete signal, or terminate without a success marker and record incompleteness when no such signal exists. Do not replay inference to fabricate a completed stream.

### D11 — Extend resource authority for reconstructible continuation

Projection returns the client-visible view plus the native material needed to reconstruct permitted next actions. Retain full ordered native blocks where required, not merely extracted strings or signatures. Bind continuation to tenant, serving identity, contract/codec revision, parent/branch, dependencies, pending calls, expiry, and correspondence with client-visible history.

Support native continuation, explicitly negotiated OLP handles, or a tested extension path. Do not infer client capability from an arbitrary user-agent string or count fields that its serializer discards. An optional lightweight OLP client helper may implement the negotiated carrier; native API access must work without it. Define and version the carrier's expiry, integrity/confidentiality, replay/branch, and error behavior without exposing OIF as the public wire format.

Validate history edits against retained dependencies; reject or explicitly restart incompatible branches rather than replaying deleted context. Permit independent histories/branches where the native API allows them. Serialize or compare-and-swap actual shared upstream mutations, not every stateless conversation. Recheck tenant/resource authorization and revocation on every lookup. Reuse existing durable mappings and admitted credential references; do not build a second resource store.

### D12 — Make actionable tool delivery recoverable when promised

For resumable translated tool workflows, required native dependencies must be recoverable before exposing an actionable tool call or its continuation handle. Wait only for dependencies of that action. A server-stored handle requires its durable state before publication; a client-carried complete dependency may not need server persistence. Do not add a persistence transaction to every token or every stateless native request.

A client that acts on partial tool arguments cannot be assumed to respect an unimplemented ready marker. Negotiate a readiness contract, buffer the actionable representation until safe, or reject the stronger workflow contract before dispatch. Record enough accepted-work information to reconcile/replay delivery where upstream support permits it. A tool-ready record cannot retroactively resolve a provider invocation lost before that boundary. Do not claim exactly-once tool execution.

### D13 — Separate upstream acceptance from client observation and keep one retry owner

Track not-sent, outcome-unknown, accepted, and terminal upstream states separately from unobserved, partially observed, actionable, and terminal client states. Response commitment remains an independent constraint on Failover. Provider work may begin before any client bytes arrive; partial upload or a lost response can produce an ambiguous outcome.

Only the existing shared Attempt owner initiates additional Attempts. Use qualified upstream idempotency/reconciliation only to resolve or safely replay the same accepted operation; proxy-local deduplication is insufficient. Do not turn that recovery mechanism into fresh inference on another target. Failover remains prohibited after response commitment or while the upstream outcome remains ambiguous under the domain contract. Do not hedge effectful work, silently change models/accounts, or regenerate visible text as a resume mechanism. Preserve local quota refusals, skipped-candidate rules, reservations, settlement, and all-attempt usage attribution. Provider-native usage categories remain distinct from estimates.

### D14 — Compose execution dimensions instead of multiplying engines

Separate delivery (unary, incremental, duplex), lifetime (request-scoped or durable), submission (immediate, queued, batch), and effects (inference, resource mutation, hosted-tool activity). Implement a small set of concrete runners using those declared combinations. A background generation can stream, and a batch can contain embeddings; neither belongs to an exclusive catch-all category.

Reuse current media/resource workers and process lifecycle behavior. Each admitted combination specifies framing, cancellation/deadline propagation, retention, resource ownership, partial failures, expiry, retrieval, and retry rules. Cancellation is not proof that the provider stopped or refunded work. Provider-accepted durable operations survive client disconnects only under their declared contract.

### D15 — Support operation families without modality degradation

Generation/structured output retain ordered inputs, schemas, tools, reasoning dependencies, candidates, citations, refusals, and finish status. Token counting remains a separate operation with native counts distinguished from estimates. Embedding payloads retain input task/prefix/truncation controls, logical and storage shapes, dtype, packing/quantization, dense/sparse/multivector layout, and per-input ordering. Do not cast all representations to floating-point vectors.

Rerank preserves exact query/documents, original IDs/indices, top-N, native score representation/order/ties, and truncation settings; the kernel imposes no universal score range or cross-model normalization. Moderation/classification/scoring preserve category/schema identity, native values, thresholds, and result scope. No operation is split/recombined without a qualified separability contract that includes ordering, partial failure, and relevant set-level semantics.

Image, audio, video, and document operations preserve original assets, masks, codecs, timing, modality controls, and native results/resources. Asset references carry byte identity or explicitly scoped native/caller URLs, ownership, type, expiry, and authorization. Acquisition or conversion is explicit and policy-controlled; OCR, resampling, transcoding, resizing, and frame sampling are not neutral adapter conveniences. Realtime contracts include VAD, interruption, turn boundaries, tools, and media timing as well as event contents.

### D16 — Compile typed provider configuration and effective defaults

Separate connection configuration, provider-model serving bindings, operation/dialect defaults, request-owned controls/native options, policy assertions, and client contracts. Provider profiles own schema and UI metadata. Preserve existing credentials, pools, discovery, certification workflows, draft revisions, and activation safeguards while making evidence more precise.

Resolve documented inheritance and provenance before dispatch. Explicit caller values cannot be silently overwritten by defaults. Management reset/unset is not native JSON null. Arrays and tool/schema definitions replace atomically unless an operation-owned merge is explicitly defined. Reject collisions between shared controls and native options rather than applying last-writer-wins. Defaults that fill declared omissions must appear in the effective-native baseline and inspector; target-native omission and source-defined default mapping are distinct contracts. Budget policies reject inadmissible requests instead of shrinking generation/reasoning settings.

### D17 — Close network/header gaps without weakening security

Configure semantic/API-version/feature headers and query settings independently of authentication. Schema-own or allowlist those values and reserve authorization, host, hop-by-hop, tenant, and security-sensitive routing controls. Refreshing a secret must not rewrite semantic configuration; changes to the upstream principal or resource scope are explicit serving changes.

Provide per-connection HTTP/SOCKS proxy, trust roots, mTLS, and supported connect/TLS/response-header/idle deadlines and connection-pool settings. Preserve DNS/egress policy, redirect controls, body limits, and tenant isolation. Remote DNS resolution through a proxy requires enforceable destination policy at that boundary; local DNS pinning alone is not sufficient. Treat native option payloads as data, never executable configuration or unrestricted destination overrides.

### D18 — Make policy/fidelity compatibility an activation invariant

A strict route cannot activate with hidden input/output redaction, prompt rewriting, automatic model substitution, or other semantic mutation policy. Pure validation or explicit blocking remains available and has truthful outcome classification; blocking after dispatch may still incur provider usage and must not be presented as pre-dispatch rejection.

Retain deliberately transformed products under an explicit visible contract with their own effective baseline. Do not silently move a strict route into that class when configuration changes. Native unknown-field forwarding is permitted only when the profile can uphold the route's authorization and policy requirements. Fidelity never exempts a request from access or egress controls.

### D19 — Bound runtime work and protect sensitive state

Use bounded queues, backpressure, cancellation, and explicit byte/buffer ownership. Some client protocols require accumulated final output, so every plan declares memory/spool limits rather than promising universal constant memory. Spooling requires explicit privacy/retention permission; overflow is a truthful limit/incomplete outcome, not event dropping. Isolate long media/stream traffic from critical credential/control activity where resource sharing would cause starvation.

Server-stored continuation requires encryption, tenant isolation, retention/residency controls, expiry, deletion, and recovery behavior. Sensitive client-carried state requires integrity and confidentiality as applicable and a declared size limit. Keep opaque reasoning material out of ordinary logs. Use tenant-scoped keyed fingerprints when needed and bounded caches; do not build cross-tenant prompt/state deduplication.

### D20 — Optimize only within the semantic contract

Keep OIF in process, retain native source spans lazily, construct outbound content once, precompile profiles/mapping templates, reuse secure isolated connection pools, and process events with small incremental state machines. Do not rediscover schemas, reflect through registries, rebuild generic JSON, or synchronously access control-plane storage for every token.

Establish a reproducible benchmark baseline before adopting numeric latency/throughput budgets. Measure against a minimal authorized native relay with fixed hardware, payload classes, concurrency, TLS/connection reuse, and network placement. Record native and translated distributions, not just averages. Performance improvements may not come from prompt compression, semantic caching, reduced reasoning, media alteration, or weaker-model substitution. Mandatory security/state barriers remain part of the measured product. Do not promise zero added latency or reuse the unmeasured targets from the first proposal.

### D21 — Make effective execution visible in the console and management API

Retain Svelte, feature ownership, dirty-state protection, ETags, drafts, and explicit activation. Add schema-driven connection/profile/model-binding forms with a synchronized advanced editor and accessible errors. Distinguish hosting/API modes and semantic headers from credential configuration. Use the existing management-contract generation mechanism; update exports/imports and deployment configuration consistently.

Extend route simulation with a no-inference plan inspector showing the ingress/OIF/egress and return path, effective native request with safe redaction, value provenance, introduced defaults, semantic requirements, eligible/ineligible route targets, buffering/state obligations, client carrier, and evidence scope. Dry runs may perform explicitly documented metadata/auth checks but must not execute inference, create provider jobs, or run tools. Display billed probes/evaluations separately. Configuration diffs highlight model-significant changes, account/region changes, mutation-policy conflicts, and state incompatibility.

Replace a universal provider-quality badge with discovered/declared/tested/stale/unknown evidence and separate native/translation coverage. Add operation-specific playground views for vector shape/dtype, rerank identities/scores, media resources/timelines, realtime events, and tool/branch correspondence. Never display opaque sensitive state merely to demonstrate that it exists.

### D22 — Publish evidence and useful coverage, not vacuous success

Maintain a versioned operation/profile/mode/client compatibility matrix and a fixed representative workload inventory. Initial coverage includes the existing supported operation/surface combinations, the named native/cloud profiles, and the reasoning/tool, non-chat, media, and duplex vertical slices below. Each entry records native/qualified/incompatible/unavailable status and constraints; a future unintegrated API is not claimed supported.

Report admitted workload coverage, qualified completions, preflight incompatibilities, runtime contract violations, ambiguous outcomes, quality comparisons, and latency/resource overhead separately. Connectivity probes do not establish intelligence parity. Runtime drift invalidates or narrows affected qualification without unnecessarily disabling unrelated authorized native paths. Do not count rejected workloads as passing quality samples or silently remove difficult fixtures from the denominator.

### D23 — Deliver incrementally with reviewed compatibility changes

Use six gated slices: (1) freeze independent fixtures, turn recorded counterexamples into preserve-or-reject tests, and capture baseline benchmarks; (2) introduce source-preserving OIF and identity plans behind existing adapters; (3) link profiles/configuration and implement qualified planning with a complete reasoning-enabled streaming tool workflow; (4) prove operation independence with packed/sparse embedding and rerank behavior; (5) integrate durable media/resource and duplex contracts; (6) complete console evidence/inspection, release qualification, and migration tooling. Each slice includes its public API/configuration, tests, and usable behavior rather than leaving all integration until the end.

New fidelity routes default to strict contracts. Existing published routes retain explicit legacy behavior until reviewed migration; the system must not relabel them faithful without qualification. Plan-only shadow comparison must not submit a second inference. Preserve compatible codec/profile revisions while resources depend on them, but always apply current revocation and permissions. Use forward-only, expand/migrate/contract storage changes with mixed-version and rollback tests; do not make rollback depend on resurrecting deleted credentials. Update generated contracts, deployment schemas, configuration round trips, operational guidance, and the domain glossary alongside implementation.

## Testing Decisions

### Primary seam and prior art

The primary acceptance seam is the published inference API through the real gateway to an independently scripted local provider, then back through the supported client and its next request. Configure providers, credential slots, routes, and policies through public management APIs. Assert captured provider-bound requests, client-visible responses/events, subsequent native requests, provider-side effects, and externally visible accounting/resource outcomes. Do not assert private struct layouts, helper-call order, or which internal package implements a mapping.

Reuse the existing provider/native surface parity harness, native embeddings/rerank/image tests, response/batch/realtime/Bedrock lifecycle suites, language-neutral protocol corpus, content-policy tests, resource-scope and credential-authority tests, official JavaScript/Python SDK fixture servers, process/recovery harness, and console browser journeys. Some existing parity checks decode using production codecs; the new reference side must remain independently authored and must not reuse the same mapper as its oracle.

Use that one semantic scenario model wherever practical. Existing SDK tests are required to observe real serialization; process/service tests are required to observe durability and revocation; browser tests are required for UI behavior. These are existing external boundaries, not a reason to expose internal test-only APIs. Add focused operation-contract tests or bounded state-machine property tests only where they materially improve combinatorial coverage; keep expectations externally meaningful.

### T01 — Convert the recorded losses into preserve-or-reject regressions

For each case, assert correct native/qualified behavior or a precise pre-dispatch incompatibility with zero provider dispatch; success after silent loss must fail the test. Include positive qualified/native controls so blanket rejection cannot pass the suite.

| Scenario | Required observable outcome |
| --- | --- |
| Text before a tool call and text after it | The target sees the qualified original ordering and relationships, or the request is rejected before dispatch. |
| Distinct system/developer instruction scopes | A qualified scope-preserving mapping is used, or incompatibility is explicit; keeping strings while silently collapsing scopes is insufficient. |
| Structured-output name, description, dialect, and strictness | Required metadata reaches the effective native invocation, or the unavailable mapping is rejected. |
| Absent, null, zero, false, and empty values | Only equivalences declared by the relevant dialect contract may erase distinctions; unsupported public payload forms are not treated as valid merely to exercise a decoder. |
| Native token-limit and reasoning controls | Original semantic scope survives lowering; unknown equivalence is rejected rather than guessed from names or scalar values. |
| Unknown native versus translated fields | Authorized native identity forwarding preserves them; translated obligations cannot be discharged by silently storing or dropping them. |
| Mutation policy attached to a strict route | Activation fails with a fidelity-policy conflict; an explicitly transformed route remains visibly distinct. |

The earlier five probe results are characterizations of the reviewed snapshot, not passing fidelity tests or measured quality regressions. Reproduce them under the repository's supported toolchain before relying on them as current regressions.

### T02 — Qualify whole SDK interactions, not isolated response JSON

Run the decisive reasoning-enabled streaming tool workflow through an actual supported ingress client. Use scripted upstream events containing mixed content, parallel calls, late native state, tool arguments, citations, refusal paths, and multiple candidates. Inspect the next provider-bound request after the client returns tool results. Compare complete required native dependencies, order, identity, settings, and history against an independent direct-native fixture.

Test both native continuation and a negotiated translated carrier. The same translated workflow through a client that drops required state must fail before dispatch, without disabling reasoning or changing API mode. Test edited history, branches, removed calls, replayed handles, expiry, tampering, wrong tenant/account, route changes, credential refresh, and revocation on a pinned revision.

### T03 — Inject faults at external acceptance, actionability, and recovery boundaries

Inject connection loss before sending, during upload, after provider acceptance, before/after durable state persistence, before/after publishing an actionable call, during cancellation, and before terminal delivery. Crash and restart gateway/worker processes using existing recovery seams. Assert no actionable server-stored handle precedes recoverable state, and a valid published handle reconstructs the same permitted continuation after restart.

Observe provider-side accepted-work counters and resource IDs to detect duplicate dispatch. Verify ambiguous outcomes do not cause blind retries; configured Attempts and local quota refusals retain their existing budget semantics. Verify response commitment forbids Failover, revoked credentials remain revoked, and retrievable work is reconciled only under the provider's qualified contract. No test may infer exactly-once provider execution solely from OLP's accounting deduplication.

### T04 — Cover operation and execution independence

Test exact asset/tensor bytes and metadata, logical versus packed storage dimensions, integer/binary/sparse/multivector embeddings, task/prefix/truncation controls, ordered per-input results, rerank document identities/native scores/ties, moderation categories, and native token counts versus estimates. No test oracle may normalize away a required representation difference.

Cover image masks, audio/video timing and codecs, document assets, duplex interruptions/VAD, durable streaming responses, batch partial failures, files, expiry, cancellation, and retrieval. Include slow readers/writers and disconnected clients. Verify no hidden conversion, candidate-set splitting, result recombination, or unqualified timing change. Keep existing native operation/surface inventory coverage while marking intentionally refused legacy translations explicitly.

### T05 — Validate configuration, cloud profiles, and security through public behavior

Exercise profile activation and the captured final endpoint/body/headers/signature for supported cloud/API combinations. Check header authentication independence, reset/null/default behavior, atomic arrays/schemas, collision errors, safe secret refresh versus account changes, config export/import, generated management-contract parity, and no-inference simulation.

Use controlled TLS endpoints, proxies, DNS behavior, trust roots, and client certificates to verify networking options and egress protections, including remote-proxy resolution. Test tenant/resource authorization, reserved native-option fields, malicious asset URLs, unknown hosted-tool options under restrictive policy, body/parser limits, and opaque-state log redaction. Use existing authorization and process seams rather than production bypass flags.

### T06 — Test the console at user-visible boundaries

Extend existing browser journeys for schema-driven configuration, advanced editor synchronization, dirty drafts/ETags, invalid activation, effective-native previews, provenance, incompatible route targets, state-carrier requirements, revision diffs, evidence scopes, and operation-specific playgrounds. Test accessibility and keyboard use. Verify that a dry run creates no inference/job/tool effect and that billed evaluation actions are visibly distinct. Neither secrets nor opaque native state may leak through previews, errors, or history.

### T07 — Use independent references and deliberate corruption

Keep hand-authored or independently captured native requests/results/events with protocol/profile revisions and provenance. Do not derive both expected and actual output through the same encoder or regenerate the frozen reference inventory from the new implementation. Add new versioned evidence without rewriting historical evidence to match code.

Deliberately delete, duplicate, reorder, relocate, or alter model-significant fields, defaults, controls, tool identities, and terminal events in test mutations; the semantic acceptance checks must fail. Property-test ordering, precision, presence, reconstruction, and bounded event grammars across feature combinations. Test unknown event/type drift and stale evidence explicitly. Round-trip serialization by itself is not a fidelity oracle.

### T08 — Establish scoped intelligence and quality evidence

Live statistical quality studies are optional follow-up work for release. Ship all 66 user stories and the product decisions above with deterministic conservation, complete supported interactions, and honest evidence states. Deferring a study does not defer a feature or authorize a parity claim, reduced coverage, a known semantic defect, or weakened security/recovery checks.

Quality qualification uses separately authored direct-native and OLP invocations to the same observable serving identity, with the same effective controls, tools, assets, and state. Establish direct/direct variability first, then randomize and interleave direct/OLP trials. Record provider/model/API revisions and observable alias/fingerprint drift; a matching seed is not assumed to guarantee determinism.

Pre-register workloads, operation-specific metrics, sample design, confidence intervals, noninferiority margins, and treatment of inconclusive results before comparison. Known semantic differences have zero tolerance and cannot be excused by a favorable average score. Use task/tool/long-horizon success for generation, representation and retrieval metrics for embeddings where relevant, ranking metrics with stable document IDs for rerank, and appropriate media/realtime evaluations. Do not choose thresholds after seeing results or treat failure to detect a difference as proof of equality.

Live calls require explicit credentials and cost/privacy approval and remain outside ordinary CI. Use non-sensitive approved fixtures rather than duplicating production inference. Missing or inconclusive evidence stays visibly unknown and blocks the corresponding empirical parity claim; it does not block release when the mandatory deterministic and functional gates pass. Unexplained quality regressions block qualification of the affected empirical claim; any identified product correctness defect must still be fixed before release.

### T09 — Benchmark and enforce bounded resource behavior

Require a bounded representative performance smoke on the release candidate: exercise the authorized native relay, native and translated gateway paths, streaming and slow readers, a large asset, and pre-dispatch rejection. Record the command, source revision, duration, successful/rejected/dispatch counts, and available latency, allocation, and resource observations. Investigate stalls, unbounded growth, unexpected dispatch or failure, and clearly material regressions before shipping. Short-run timings are descriptive; they do not establish stable tails, a statistical noninferiority result, or an advertised latency guarantee.

Resource correctness remains a release gate: test queue/spool and body/state limits, cancellation, slow peers, resource cleanup, explicit overflow/incomplete outcomes, and isolation of sensitive control activity. Retain functional continuation-barrier, media, durable-resource and realtime tests, including recovery, SDK and browser checks. Never obtain passing numbers by dropping fields, changing the model, bypassing security/state barriers, or excluding rejected work.

Long repeated captures, paired source studies, detailed tail/jitter/throughput surveys, and statistical performance qualification are optional and nonblocking for release. When undertaken, capture native-relay and OLP baselines and freeze workload-specific numeric criteria before evaluating a replacement; record hardware, concurrency, payloads, network/TLS conditions and duration. Preserve original fixture inventories, baseline bytes, budgets, and failed/invalid outcomes. An old failed limit remains failed under that study; a smoke pass or revised release criterion must not relabel it. No earlier unmeasured millisecond target is an acceptance result.

### T10 — Prove extensibility and migration without reducing coverage

Add a fixture provider using an existing dialect through profile/binding/registration only; add a new fixture dialect without provider cases in operation kernels; add a non-generation operation without changing generation types. The externally visible behavior must pass the same primary seam. Review dependency direction as an architectural constraint, not a substitute for behavioral tests.

Exercise old/new mixed revisions, legacy-to-strict migration review, plan-only shadow comparison, active-resource continuity, forward-only storage transitions, and rollback with current revocation. Compare the fixed operation/workload inventory before and after migration. Existing integration suites must fail rather than silently skip when explicitly selected without required services. Run repository formatting/type/contract checks, unit/protocol tests, race tests, SDK/service/recovery suites, and browser journeys appropriate to each slice; report actual execution separately from fixture/test existence.

### Completion gates

- **G1 — Conservation:** Every recorded counterexample has a native/qualified positive case and preserve-or-reject negative coverage; consumed information, introduced behavior, and structure are all accounted for. Covered by T01 and T07; supports stories 1–12 and 47–48.
- **G2 — Complete interaction:** Native and negotiated translated reasoning/tool workflows pass real-client next-turn tests, unsupported clients fail before dispatch, and recovery honors actionability/acceptance boundaries. Covered by T02–T03; supports stories 13–24 and 44–46.
- **G3 — Operation breadth:** Non-chat representations, media, durable resources, and duplex behavior pass their declared contracts without a chat-shaped dependency or reduced inventory. Covered by T04 and T10; supports stories 25–40.
- **G4 — Configuration/security:** Typed options and cloud/network compositions work through public configuration while authorization, egress, policy conflicts, and secret handling remain intact. Covered by T05; supports stories 40–50.
- **G5 — Usable control plane:** Console/API inspection, evidence, drafts, configuration round trips, and operation playgrounds reflect actual behavior without inference side effects during dry runs. Covered by T05–T06; supports stories 54–59 and 66.
- **G6 — Honest quality/performance:** Deterministic conservation, bounded representative performance smoke, and resource/overflow correctness pass. All feature, security, recovery, SDK, browser and inventory gates remain required. Live quality and long statistical/performance studies are optional follow-up; unknown/inconclusive cases, historical failures/invalid runs and rejected workloads remain visible and prohibit unsupported empirical claims. Covered by T07–T09; supports stories 51–53 and 60–62.
- **G7 — Sustainable delivery:** Extension demos, mixed-version recovery, explicit legacy migration, generated contracts, documentation, and existing required suites pass with no silent coverage shrinkage. Covered by T10; supports stories 35–39 and 63–66.

The full feature is not complete with only an OIF type definition, native passthrough, one successful chat call, or a broad rejection policy. Incremental slices may ship behind explicit contract/evidence status, but the issue's completion requires the declared breadth and gates above. Each advertised profile/mode must have concrete evidence; unimplemented future protocols are not included in a universal compatibility claim.

## Out of Scope

- Equality of intelligence between different providers/models, proof of unobservable neural execution, deterministic sampled answers, immutable behavior behind an unversioned provider alias, or literally zero added proxy latency.
- Automatic prompt rewriting/compression, history truncation, media conversion, schema repair, reasoning-budget approximation, answer caching, or weaker-model substitution under a strict contract. Existing explicitly transformed products may remain, but expanding their transformation catalog is not part of this work.
- Arbitrary cross-model migration of opaque reasoning state; provider-side exactly-once inference or external-tool execution without a real upstream/client contract; treating local deduplication as either guarantee.
- Implementing a general agent orchestration framework, autonomous tool runner, model-training/fine-tuning platform, inference engine, compiler optimizer, graph database, runtime untrusted-plugin VM, microservice mesh, or language/framework rewrite.
- Shipping undocumented future protocols automatically, claiming every possible protocol/model pair is equivalent, or treating unknown native data as portable solely because OIF retains it. Extensibility is in scope; nonexistent mappings are not claimed implemented.
- Paid live evaluation, production shadow inference, or production configuration changes without explicit cost/privacy/operator authorization. Plan-only comparison and deterministic local testing are in scope.
- Replacing the existing route/credential/accounting/resource authority, rewriting historical frozen reference evidence, silently upgrading legacy route semantics, or creating a separate public universal OIF API.
