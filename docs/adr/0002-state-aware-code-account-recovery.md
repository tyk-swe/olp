# State-aware code account recovery

Strict pins preserve ownership but can strand new work on exhausted accounts. The accepted [#522 target](https://github.com/tyk-swe/olp/issues/522) permits bounded recovery only with proof of non-execution and valid continuation state on an eligible destination, preserving authorization, exact-model policy and required durable affinity. Recovery distinguishes refresh rejection, quota exhaustion, cooldown and transport ambiguity, and respects supported reset and Retry-After observations. The absence of client-visible output is insufficient proof. Accepted work, partial output and uncertain dispatch never replay automatically, and unportable account-owned state never moves. Unsafe cases retain usage uncertainty and return an actionable outcome even after cancellation or socket loss.
