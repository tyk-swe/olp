# State-aware code account recovery

Strict pins preserve ownership but can strand new work on an exhausted account, so the accepted [#522 target](../develop/plans/code-mode-parity.md) permits bounded recovery only with proof that the request has not executed and its continuation state is valid on an eligible destination, preserving current authorization, exact-model policy and durable affinity where required. Recovery must distinguish refresh rejection, quota exhaustion, cooldown and transport ambiguity, and respect supported reset and Retry-After observations. Absence of client-visible output is insufficient proof, so accepted work, partial output and uncertain dispatch never trigger automatic replay, unportable account-owned state never moves to another account, and unsafe cases retain usage uncertainty and return an actionable outcome even after cancellation or socket loss.
