# MCP module seams and hand-rolled streamable client

Project-owned MCP support stays split across registration in `internal/mcpservers`, tool execution in `internal/mcp`, and personal grants in `internal/mcpgrants`, with configure-time OAuth, Entra, and delegation validation owned by registration and the call-time token exchange, renewal, and signing owned by grants, because the two phases share concepts and the configuration types in `internal/grants/config` but no behavior, and merging them would couple the management write path to the dispatch hot path. Upstream servers sit behind the `mcpservers.Upstream` interface so catalog certification can be tested without a live server, and certification and snapshot compilation share one tool-schema compiler in `internal/routing` so a certified schema always compiles at publish. The streamable HTTP client remains hand-rolled behind that interface even though the official Go SDK already serves the stdio and legacy SSE transports, because the SDK client negotiates its newest protocol version, retries with reconnection, and opens a standalone SSE stream, while OLP pins exact protocol versions per registered transport, never falls back from modern to legacy certification, and dispatches each tool call exactly once.
