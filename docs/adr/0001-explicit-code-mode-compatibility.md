# Explicit code-mode compatibility

The native-only contract blocks otherwise suitable coding workflows, so the accepted [#522 target](https://github.com/tyk-swe/olp/issues/522) permits explicit protocol translation and model alias policy while keeping native forwarding the default and preserving published behavior until deliberately changed. Identity or prompt changes require a separate opt-in explaining the affected behavior and account suspension risk, authorized for eligible shared accounts by the existing route administrator without a contributor approval workflow. Translation must reuse existing protocol primitives and preserve code-mode authority, accounting and required semantics, while paid API participation needs separate authorization and monetary policy.
