# Strict OpenAI Realtime WebSocket contract

Strict `/v1/realtime` uses an operation-owned `openai-realtime` contract on an explicitly versioned direct OpenAI or Azure v1 profile. A Chat or Responses generation dialect does not interpret duplex events. The published target must certify `(realtime, openai, realtime)` and compile a native `/realtime?model=` address. Azure v1 uses `/openai/v1/realtime?model=`; Azure preview's deployment and dated API-version address is outside this contract. [OpenAI's WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets) and [Microsoft's Azure Realtime guide](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/realtime-audio-websockets) document these separate native addresses.

Activation rejects profile-less, preview-hosted, or uncertified targets; content-policy rules the relay cannot inspect; provider semantic headers/query overrides; and realtime defaults that would be silently ignored. Request admission accepts one published `model` and optional OLP accounting attribution. It refuses extra or repeated query controls, semantic headers, and WebSocket subprotocols before opening the provider connection. In particular, `OpenAI-Beta`, `OpenAI-Safety-Identifier`, and per-request voice/routing controls have no qualified binding here. OpenAI's [GA migration guide](https://developers.openai.com/api/docs/guides/realtime) explicitly removes the beta header; the safety identifier requires a separately reviewed binding rather than silent removal.

After admission, the relay forwards each WebSocket message type and payload bytes in order with synchronous backpressure. A bounded observer reads response IDs, terminal events and usage to classify completion; it does not rewrite frames or interpret VAD, interruption, audio or tool controls. Common flat events use a duplicate-safe, UTF-8-validating fast path; nested or escaped events use the full OIF validator. An ambiguous event cannot discharge a pending response or turn an incomplete normal close into success. The model address is the reviewed route-to-target binding. Both directions have the configured bounded frame read limit and independent write deadlines; the session has a deadline and heartbeat. Current API-key route authority, the pinned provider credential, and any configured network credential's revocation are rechecked during the session. Abnormal provider/protocol termination records an incomplete Attempt, while client disconnect records cancellation. Neither case is converted to a successful model response or a new Attempt.

`TestStrictRealtimeNativeIdentityAndRefusals` creates and certifies real provider configurations and activates strict routes through the public management API for both `openai-responses` revision 1 and `azure-v1-responses` revision 1. Local scripted providers compare exact client frame bytes and return exact native session/VAD, interrupted-response, tool-output, audio-timing frames. The client compares each resulting frame byte-for-byte and in order. Extra query and semantic-header controls produce structured pre-dispatch refusals with zero provider dials; an abrupt client disconnect produces one cancelled Attempt. `internal/realtimecontract/contract_test.go` covers activation and handshake refusals independently of the gateway.

These deterministic fixtures establish scoped same-dialect transport identity, refusal, and accounting behavior. They do not test a live model's speech quality or every OpenAI/Azure event schema revision, cross-dialect translation, WebRTC, sideband control, or session resumption. The frozen lifecycle-stress-v1 reference used a profile-less video fixture and cannot serve as a true strict candidate; the separately frozen registered-profile v2 reference supplies the criteria for strict latency/jitter comparison. No paid inference was performed.
