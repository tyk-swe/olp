# OpenLLMProxy consolidated static audit

**Merged sources:** three independently generated reports formerly stored as `1.txt`, `2.txt`, and `3.txt`

**Last refreshed:** 2026-07-31

**Scope:** unresolved findings in the Rust gateway/control plane, storage, providers/protocols, Svelte console, Helm and Compose deployment, operational scripts, tests, and CI

**Revision note:** refreshed against `0d173f7b6b37283d16772ba1a5546fb76c8acc98` plus the current uncommitted audit patch. Findings closed by that patch were removed after code and focused-test verification; retained line references are review loci and may move before commit.

## Status and merge policy

This is a deduplicated unresolved static-analysis backlog, not runtime proof. Duplicate findings were collapsed by root cause, unique findings from the focused reports were added as `A-*`, and the broad edge-case inventory remains as `E-*`. The 2026-07-31 refresh removed entries directly closed by the current patch and narrowed entries whose original claim was only partly closed.

`Confirmed` means a source report considered the control/data flow direct. `High confidence` still needs an executable regression test. `Test required` and `Contract-dependent` are hypotheses, not proven defects. Validate each finding against the current tree before changing production behavior.

## Executive priority

1. **A-002:** live media jobs can block emergency credential containment.
2. **E-095 / E-097:** a successful upstream create can still lose its only durable recovery and cleanup identity during a database outage.
3. **E-018:** limit release and reconciliation still rely on one-shot short operations.
4. **A-011 / A-012:** request retention and configuration-list query amplification remain database scaling risks.
5. **A-009 / A-014 / E-104:** key and identity-provider rotation still lack overlap or last-known-good availability contracts.
6. **E-040 / E-042:** process death can strand spool trees and make logical accounting understate disk use.
7. **E-128:** recognized OpenAI Responses stream-event extra fidelity remains incomplete.
8. **E-082 / E-087:** bounded but potentially long global pricing writes and unbounded positive pool sizing remain operator-risk contracts.

## Severity and confidence

- **Critical:** credible release-wide outage or destructive-data risk in a normal supported workflow.
- **High:** can lose accounting or durability, orphan or duplicate billable work, cause broad availability failure, or permanently skip data.
- **Medium:** material correctness, availability, security-state, operability, or resource-amplification failure.
- **Low:** bounded compatibility, UX, maintainability, or defense-in-depth issue.
- **Disputed:** another source report identified a control that may invalidate the claim; reproduce before filing.

# Additional findings absent from the edge-case inventory

### A-002 — Live asynchronous media jobs can block compromised-credential containment

**High · Reported confirmed** — Credential rotation, revocation, provider disablement, and route changes are rejected while non-deleted jobs retain historical references (`crates/storage/src/configuration/resources/credentials.rs:25-158,292-314`; `provider_lifecycle.rs:324-367`; `resources/providers.rs:184-213`; `route_lifecycle.rs:416-470`). Jobs may remain relevant for thirty days.

**Fix / gate:** add an owner-only forced-containment operation that disables new traffic, tombstones or cancels affected jobs, publishes a safe runtime, and emits a high-severity audit event without requiring the compromised secret to remain active.

### A-004 — Distributed login abuse amplifies durable audit writes

**Medium · Confirmed; deployment-dependent** — The global bucket permits 10,000 admitted attempts per minute across replicas, and admitted invalid or failed attempts create durable audit rows. A distributed attacker can therefore translate the admission allowance into sustained database writes. Password work is already bounded by a measured process-wide semaphore and the public management admission limit.

**Evidence / review locus:** `crates/storage/src/identity/auth_admission.rs:7-12,65-105; apps/olp/src/management_api/auth.rs:28-39,267-320,639-655; crates/storage/src/store/sessions.rs:60-78`

**Fix / gate:** lower global admission to sustainable audit-write capacity. Aggregate or sample anonymous failures and batch or partition their retention.

### A-009 — API-key HMAC rotation has no verification overlap

**Medium · Reported design debt** — `crates/storage/src/security.rs:285-427` models one HMAC key. Because plaintext API keys are not retained, replacing it invalidates every stored digest and keyed bootstrap identity immediately.

**Fix / gate:** version digests, retain bounded verify-only keys, and provide an audited reissue and retirement workflow.

### A-011 — The partitioned requests table has only an ever-growing default partition

**Medium · Reported architecture debt** — `migrations/0001_initial.sql:297-320` declares range partitioning but creates only `requests_default`; no reported migration or runtime manager creates future partitions.

**Fix / gate:** create time partitions ahead of use, monitor default spill, and expire data by detaching or dropping partitions.

### A-012 — Configuration list endpoints perform hundreds of database round trips

**Medium · Reported confirmed** — API-key and route listing paths use `1 + 3N` or `1 + 4N` query patterns (`configuration/resources/api_keys.rs:4-54`; `resources/routes.rs:4-53,344-475`). A 100-item page can issue roughly 301–401 queries.

**Fix / gate:** batch child reads with `ANY($1)` and group results in memory; add query-count assertions.

### A-014 — Secret changes neither roll pods nor reload long-lived keys

**Medium · Reported confirmed for the chart** — Secret references and volumes in `deploy/helm/templates/workloads.yaml:87-107,136-174` have no rollout version/checksum, while the process loads master, HMAC, and bootstrap keys at startup.

**Fix / gate:** define an explicit immutable-secret/keyring rotation workflow that stages overlap, rolls pods, verifies readiness, and then retires old keys.

### A-015 — Operator-facing names accept bidi, control, and invisible Unicode

**Medium · Reported confirmed UI/audit risk** — Display-name and configuration-name validators generally trim and length-check but do not reject controls or bidi overrides (`management_api/auth.rs:592-620`; `access.rs:860-884`; `configuration/validation.rs:9-55`).

**Fix / gate:** centralize normalization for human-facing identifiers, reject control/bidi/most zero-width format characters, and show stable IDs in security-sensitive views.

### A-016 — Default control-plane deployment is a single disruption-sensitive replica

**Medium · Reported confirmed default** — `deploy/helm/values.yaml:73-93` defaults control to one replica with its PDB and topology spread disabled.

**Fix / gate:** provide a production default/profile with at least two control replicas, a PDB, and topology spread; keep single-node settings explicitly developmental.

### A-018 — Pricing uses request completion time

**Medium · Policy ambiguity** — Gateway telemetry assigns the completion timestamp, and pricing binds it as the observation time, so a long request crossing a price activation boundary is billed at the finish-time price.

**Evidence / review locus:** `apps/olp/src/gateway/telemetry.rs:471-497; crates/storage/src/request_metadata/ingestion.rs:318-350`

**Fix / gate:** normally snapshot at request start; if completion-time pricing is intentional, document and test it explicitly.

### A-019 — Cached-token accounting cannot produce reliable discounted cost

**Medium · Confirmed residual** — Usage validates and stores `cached_input_tokens`, but pricing has no cached-input rate and still charges all input at the normal price. The current patch closes the ingestion-invariant part of the original finding, not discounted billing.

**Fix / gate:** add a cached-input price and calculate cached and uncached input separately; preserve the new `cached_input_tokens <= input_tokens` regression.

### A-028 — Gateway topology spread is best-effort

**Low · Availability default** — `deploy/helm/values.yaml:64-68` uses `whenUnsatisfiable: ScheduleAnyway`, so default gateway replicas may share a node.

**Fix / gate:** use a production profile with protective spread or required anti-affinity where cluster size permits it.

### A-030 — Console aggregate collectors fetch up to 1,000 records serially

**Low · Confirmed residual** — The collector now rejects a page before crossing a 1,000-record bound, closing the original over-limit behavior. It still follows every cursor sequentially and retains the complete bounded result, so high-latency configuration sets remain a UI scaling edge.

**Evidence / review locus:** `console/src/lib/api/pagination.ts`

**Fix / gate:** use server-side search or virtualized incremental selection where operators need large configuration sets; retain the pre-append bound.

### P-003 — Several failure-mode and compatibility gates run only after merge

### P-004 — Coverage is enforced only as a 51% workspace-wide line floor

# Edge-case inventory

## 1. Listener, HTTP boundary, routing, and shutdown

### E-002 — HTTP/2 streams lack a per-stream request-establishment deadline

**Medium · High confidence** — The first request on a connection has an establishment deadline, but later HTTP/2 streams do not. A client can retain up to the configured concurrent-stream limit in incomplete establishment for the life of a reused connection.

**Evidence / review locus:** `apps/olp/src/listener.rs:36-41,256-342`

**Mitigation / regression test:** Apply header/read/body establishment deadlines per stream and test slow headers plus incomplete bodies across 100 streams.

## 2. Admission, limits, and route policy

### E-018 — Limit release and reconciliation are one-shot short operations

**Medium · Confirmed residual** — Reconciliation is now signed and idempotent, but a transient Valkey stall beyond 250 ms still leaves concurrency leased until TTL and estimated tokens charged until bucket expiry. Repeated faults can create false throttling.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:40-92; apps/olp/src/gateway/limits.rs:199-222`

**Mitigation / regression test:** Queue idempotent release/reconcile work for retry, or execute a bounded background retry with metrics and durable uncertainty accounting.

### E-019 — Multipart concurrency lease TTL derives from the maximum allowed route timeout

**Medium · Confirmed residual** — JSON admission now uses the selected route's timeout. Multipart admission reserves before the route is parsed and still derives its lease TTL from the maximum timeout among every allowed runtime route, so one long-lived route can lengthen leaked leases for unrelated multipart traffic.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs; apps/olp/src/request_admission/multipart.rs`

**Mitigation / regression test:** Parse or otherwise identify the multipart route before reservation, or use a separately bounded provisional lease that is atomically replaced after parsing.

### E-020 — Route timeout accepts practically unbounded positive i32 milliseconds

**Medium · Contract-dependent** — A valid value can approach 24.8 days. Long streams are an intentional supported use case, but no separate product contract bounds the request deadline and distributed lease TTL across maintenance windows.

**Evidence / review locus:** `crates/storage/src/configuration/route_lifecycle.rs:68-75`

**Mitigation / regression test:** Set product-level minimum/maximum timeouts and separately cap lease TTL.

### E-026 — API-key expiration uses each node’s application clock

**Medium · Contract-dependent** — Clock skew around `expires_at` can make one node accept a key while another rejects it. Invitation expiry now uses database time; the residual is the API-key hot path's documented dependence on synchronized node clocks.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:251-255; apps/olp/src/request_admission/multipart.rs:185`

**Mitigation / regression test:** Use database time for credential validity or enforce clock-health/readiness and include skew tolerance explicitly.

### E-033 — Very long allowed-route sets increase admission CPU work

**Low · High confidence residual** — JSON admission now looks up the selected route directly. Multipart admission still lacks a parsed route at reservation time and scans allowed routes to compute the fallback lease TTL, so its CPU work remains sensitive to policy cardinality.

**Evidence / review locus:** `apps/olp/src/request_admission/limits.rs:286-315`

**Mitigation / regression test:** Bound allowed-route cardinality or precompute the multipart fallback timeout in the runtime generation.

## 3. Multipart input, media spool, generated files, and streaming responses

### E-040 — Crash or SIGKILL leaves private media spool trees forever

**High · Confirmed** — Each process creates a new directory and removes it only in Drop. A node crash, power loss, abort, or SIGKILL leaves all prior files without a startup scavenger.

**Evidence / review locus:** `apps/olp/src/media_spool.rs:58-81,375-378`

**Mitigation / regression test:** Use a stable parent with ownership marker, scavenge stale process directories at startup, and monitor physical disk usage.

### E-042 — Logical spool accounting can understate physical disk usage

**Medium · High confidence** — Unlinking a file releases logical capacity while an open descriptor/handle can retain blocks. Concurrent producers can therefore stay under the logical cap while physical usage remains above it.

**Evidence / review locus:** `apps/olp/src/media_spool.rs; apps/olp/src/gateway/multipart.rs; apps/olp/src/json_media.rs`

**Mitigation / regression test:** Track live open-file ownership until close, and enforce/alert on filesystem free space independently of logical accounting.

### E-045 — Image producer failures occur after success telemetry is committed

**Medium · Confirmed residual** — A dropped or failed detached producer now makes the response body fail instead of ending as clean truncated JSON. The handler has already marked the response successful before body production, however, so request outcome telemetry does not retain the producer failure.

**Evidence / review locus:** `apps/olp/src/image_response.rs; apps/olp/src/gateway/media.rs`

**Mitigation / regression test:** Feed terminal producer status into request finalization and distinguish I/O failure, panic/task loss, and client cancellation after response commitment.

### E-047 — Streaming producer loss is classified as client cancellation

**Medium · Confirmed residual** — A dropped terminal channel now produces a body error, so clients no longer see clean EOF. If the producer task panics or disappears before finalization, metadata cleanup still falls back to `client_cancelled` instead of recording an explicit producer-loss outcome.

**Evidence / review locus:** `apps/olp/src/streaming_response.rs; apps/olp/src/gateway/execution.rs`

**Mitigation / regression test:** Carry a structured producer terminal outcome into accounting and test panic/task abort separately from a client dropping the body.

## 4. Provider and protocol translation

### E-128 — Recognized OpenAI Responses stream events lose same-surface extras

**Medium · Confirmed residual** — Unknown event kinds are preserved and replayed through `/stream/...` source extensions, but recognized events decode only canonical fields. Vendor or forward-compatible extra fields on supported lifecycle, output-item, delta, and terminal events are therefore lost on an OpenAI Responses stream round trip.

**Evidence / review locus:** `crates/protocols/src/openai/responses/stream.rs; crates/protocols/src/openai/client.rs`

**Mitigation / regression test:** Preserve unconsumed fields from recognized events as same-surface source extensions and round-trip a supported event containing an unknown nested field.

## 5. Metadata ingestion, Valkey/PostgreSQL durability, runtime loading, and pricing

### E-082 — Pricing revision creation holds a global advisory lock during serial work

**Medium · Confirmed residual** — Revisions are now capped at 1,000 entries and provider validation is batched. The implementation still performs one insert per price inside one transaction and a global pricing-writer lock, so a maximum valid request can monopolize a connection and block every pricing writer.

**Evidence / review locus:** `crates/storage/src/operations/pricing.rs:83-85,127-159,287-340`

**Mitigation / regression test:** Bulk insert and minimize the locked critical section; measure maximum-revision lock time against a bounded SLO.

### E-087 — Database pool size accepts extreme positive values

**Medium · Contract-dependent residual** — Zero is now rejected by CLI validation, but a huge positive max-connections value can still overwhelm PostgreSQL after a typo or templating error. A safe upper bound depends on replica count and the deployment's PostgreSQL capacity.

**Evidence / review locus:** `apps/olp/src/cli/config.rs:49-55; crates/storage/src/store.rs:60-68`

**Mitigation / regression test:** Define and validate an operator-supported upper bound against deployment replica count and PostgreSQL capacity.

## 6. Media-job durability and reconciliation

### E-095 — Successful upstream create can lose its only recoverable ID

**High · Confirmed residual** — Upstream-ID attachment now gets ten bounded retries with exponential delay and direct compensation attempts. Exhaustion or a crash while PostgreSQL is unavailable can still leave the reservation without the only provider ID; restart cannot discover or delete the potentially billable job.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:64-97,227-330; apps/olp/src/gateway/media_jobs.rs:62-81,182-220`

**Mitigation / regression test:** Use an idempotency key plus provider lookup, or durably record intent/result in a local/independent WAL before returning. Test crash and outage after upstream acceptance and after retry exhaustion.

### E-097 — Create failure cleanup depends on another one-shot database write

**Medium · Confirmed residual** — Cleanup-intent persistence now shares the bounded retry policy. If PostgreSQL remains unavailable through exhaustion, or the process crashes first, only logs and best-effort provider compensation retain the recovery gap.

**Evidence / review locus:** `apps/olp/src/gateway/videos.rs:227-330`

**Mitigation / regression test:** Persist state transition through a durable retry queue/WAL independent of the failing transaction path.

## 7. Identity and OIDC

### E-104 — OIDC callbacks fetch JWKS fresh with no last-known-good cache

**Medium · Contract-dependent** — A brief IdP JWKS outage disables every login and reauthentication even when the token uses a key previously fetched and still within a safe cache lifetime. Bounded stale-if-error improves availability but needs an explicit revocation/rotation freshness contract.

**Evidence / review locus:** `apps/olp/src/oidc/callback.rs:274-297`

**Mitigation / regression test:** Cache validated JWKS with issuer cache headers, bounded stale-if-error, unknown-kid refresh, and rotation tests.

### E-107 — Logout reports success even when server-side revocation fails

**Medium · Contract-dependent** — The browser intentionally fails closed by clearing its cookie and receiving 204 even when database revocation fails. The session may nevertheless remain valid if its credential is replayed from another client or a captured store, and the response does not communicate that residual.

**Evidence / review locus:** `apps/olp/src/management_api/auth.rs:444-465`

**Mitigation / regression test:** Return a failure or record durable revocation intent; at minimum communicate partial logout and alarm on the gap.

## Regression-test matrix

- **HTTP/2 establishment:** Hold later streams in incomplete header/body establishment on one reused connection; enforce a per-stream deadline.
- **Limit cleanup:** Stall Valkey beyond 250 ms during release/reconciliation; prove bounded retry or explicit uncertainty without double-applying the signed delta.
- **Multipart lease:** Give one allowed route a multi-day timeout and submit another multipart request; its provisional lease must remain independently bounded.
- **API-key clock skew:** Exercise expiry across replicas with the supported maximum skew and prove a single documented acceptance boundary.
- **Spool SIGKILL:** Kill the process with open and closed spool files, restart, and prove safe stale-tree scavenging plus physical-disk accounting.
- **Producer termination:** Abort and panic image and SSE producers after headers and partial output; bodies must fail and telemetry must distinguish producer loss from client cancellation.
- **Responses extras:** Round-trip a recognized OpenAI Responses stream event containing an unknown nested field without losing it.
- **Pricing lock:** Submit 1,000 prices and enforce a bounded global-lock/transaction SLO without writer starvation.
- **Pool sizing:** Reject or clearly diagnose a configured connection total beyond the deployment's supported PostgreSQL budget.
- **Media create crash:** Crash after upstream acceptance, after each attachment/cleanup retry, and at retry exhaustion; the provider ID and cleanup intent must remain recoverable.
- **JWKS outage/rotation:** Cache key A, take JWKS offline, validate A within the chosen stale window, then introduce unknown key B and require bounded refresh.
- **Logout revocation:** Fail database revocation while retaining a copied session credential; the API must meet the documented partial-logout contract.

## Important non-findings / narrowed assumptions

- The OIDC state, nonce, configuration-generation, and same-session security-operation bindings remain comparatively strong; no direct state/nonce bypass was found in the reviewed path.
- Production media spooling uses the private constructor; test-only/nonprivate construction is not the production default.
- Readiness intentionally remains HTTP 200 for degraded subsystems when the gateway can still serve safe traffic; the health payload and enabled-component Helm rules expose limiter and metadata degradation separately.

## Suggested repair order

1. Close the media-create identity and cleanup-intent durability gaps, then define forced credential containment for affected live jobs (`E-095`, `E-097`, `A-002`).
2. Give limit release/reconciliation a durable bounded retry path now that reconciliation is idempotent (`E-018`).
3. Address database growth and control-plane query/write amplification (`A-011`, `A-012`, `E-082`, `E-087`).
4. Define key, IdP, expiry-clock, and logout-revocation contracts before implementing overlap or stale-if-error behavior (`A-009`, `A-014`, `E-026`, `E-104`, `E-107`).
5. Add crash-safe spool ownership/scavenging and physical-disk accounting (`E-040`, `E-042`).
6. Preserve recognized Responses stream extras (`E-128`).
7. Resolve product/deployment policy choices: pricing time and cached rates, long route timeouts, login audit capacity, Unicode names, replica defaults, and topology spread (`A-004`, `A-015`, `A-016`, `A-018`, `A-019`, `A-028`, `E-020`).
8. Finish the lower-amplification HTTP residuals (`E-002`, `E-019`, `E-033`, `E-045`, `E-047`, `A-030`).
